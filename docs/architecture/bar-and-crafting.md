# 바·제조·QA 구현

[구조 안내](README.md)에서 필요한 기능만 찾아 읽으세요. 게임 동작의 기준은 [본편 규칙](../gameplay/README.md)이며, 이 문서는 구현 위치를 설명합니다.

## 바 내부 QA 데이터

단골 제조 진입은 `app/app.js:storyCraftReady`가 현재 주문과 `craft` 대기 행, 대사/선택지/완성 잔 없음, 카메라·전환 완료를 확인해 왼쪽 `.service-handle`을 표시한다. 중앙 제조 CTA는 사용하지 않는다. 클릭/Tab → 기존 서비스 패널 → 칵테일 레시피 → 제조 준비를 공통으로 사용하며, `toggleService`의 정지·드래그·튜토리얼 제한과 `openRecipes`의 제조 가능 여부 검사는 유지한다. 대사 기억용 말풍선 판단도 같은 준비 조건을 사용한다. 검증: `test-story-service-entry-ui.cjs` (`ui` 묶음).

단골 대본의 명시적 `coaster/empty_glass` 행, `craft → serve` 인접 조건 및 2인 작성 예시는 [데이터 작성 계약](../gameplay/data-and-dialogue.md#바-대본의-코스터빈잔-트리거)에 통합했다. 입력은 [잠금 조건표](../gameplay/input-locks.md)를 따른다. `core.js:barInteractionBlocked`는 대사 진행과 코스터 3분기의 동일한 입력 조건만 공유하며 일반 영업/연출 시계를 멈추지 않는다.

개발자 시뮬레이션의 **QA 99 → 영업 시작 → 바 내부 대화 선택지**에서 테스트한다. 우측 하단 바 QA 런처와 별도 통합 테스트 탭은 사용하지 않는다. `src/dev/qa/bar-qa-presets.js`가 프리셋·분야별 페이지·캐릭터별 표정 선택·실행 어댑터를 소유한다. 분야 → 테스트 → 실제 대화/제조/알림 → 완료 메뉴가 모두 기존 바 선택지와 **0.3초 홀드**로 이어진다. 완료 메뉴는 ‘다음 테스트(표정) / 다시 테스트 / 다른 테스트 선택 / 처음으로’이며 마지막 테스트에서는 다음 항목을 숨긴다. ‘다른 테스트 선택’은 방금 실행한 항목이 있는 목록 페이지로 돌아온다. 기존 CSV QA의 대사·분기·일반 영업·단골 주문·정산은 ‘기존 QA 대사·일반 영업’ 선택지로 연결한다. 외부 QA의 Tab 패널은 그대로 유지한다.

- **선택지 규격 확정: 한 화면 최대 4개, 슬롯 번호 1–4.** 분야·테스트 목록·개별 표정은 **내용 3개 + 이동 1개**로 구성한다. 중간에는 ‘다음 항목 · 다음 페이지/전체 페이지’만 표시하고 이전/뒤로를 넣지 않는다. 마지막 페이지에서만 ‘뒤로’(최상위는 ‘처음 항목으로’)를 표시한다. 마지막의 남은 내용이나 원래 2–3개인 대화에 빈 선택지를 채우지 않는다. 실제 테스트·완료·기존 CSV QA도 최대 4개다. 5개 이상인 신규 QA 메뉴는 오류로 차단하며, 항목을 잘라 버려 테스트 접근을 잃게 하지 않는다.
- 코스터: 1인, 2인 모두 주문, 2인 중 1명만 주문. 실제 `enter/say/coaster/order/craft/serve`와 드래그 검사를 사용한다. 두 주문은 본편처럼 순서대로 처리한다.
- 선택지: 재화 증감·잔액 부족·호감도 ±1·인물 등록·복합 보상·신규 목표·목표 달성·이벤트 알림. 효과는 실제 `choose/applyEffects` 경로, 알림은 공유 UI를 사용한다.
- 인물: 단골 12명의 개별 등록, 전체 해금, 0–3단계. 본편의 시바 등 호감도 미지원 규칙은 유지하고, QA 99 개발자 모드에서만 `qa_profiles_all/qa_profiles_two`로 전체 단계 표시를 허용한다. 미작성 인물 정보·없는 이미지/동작을 임의로 만들어 채우지 않는다. 일반 손님은 익명 합성 손님이므로 영구 단골 목록에 등록하지 않는다.
- 애니메이션: `characterLayers`의 바 캐릭터 7명을 고르고 개별 표정 또는 전체 순회를 대화 선택지로 실행한다. 일반 손님 남성/여성은 실제 합성 외형으로 말하기·대기를 확인한다. 개시바는 현재 등록된 바 전용 대기/말하기 이미지를 사용한다. 표정 데이터가 없는 인물을 다른 캐릭터로 대체하지 않는다. 외부 QA의 원본 프레임 검수와 바의 실제 대사 애니메이션 타이밍은 구분한다.
- 회상: 대사 또는 선택지에서 실제 조니 회상 데이터·렌더러·페이드로 진입하고, 종료 후 같은 바 대사로 돌아온다. 본편 `session.carry`, 관찰/해금 플래그는 건드리지 않는다.
- 팝업: 서비스 패널·설정·대화 기록·조작 안내·올드패션드 해금의 선택지 진입/복귀. 일차별 재료 해금·정산·잔액 부족·제조 오류는 기존 영업 상황에서 재현한다.

각 테스트 실행은 별도의 99일차 `progress`를 만들고 이전 QA 알림과 프로필 미리보기를 정리한다. 메뉴 이동·완료 메뉴에서는 결과를 유지하고 다시 테스트할 때만 초기화한다. `qa_menu/qa_route/qa_action/qa_end`는 QA 진행기에서만 소비하며 공유 `scenes/steps/bar_choices` 배열과 CSV는 수정하지 않는다. `core.choose`가 메뉴 효과를 적용하면 `qa_route`가 선택된 경로를 실행한다. 기존 CSV 허브 복귀는 같은 대화형 메뉴로 돌아온다. 재시작·본편 복귀 시 훅을 복구한다. 본편 대본을 추가하는 곳이 아니며, ‘모든 가능한 분기 조합’에 대한 자동 완전 검증을 뜻하지 않는다. 신규 기능은 이 카탈로그에 재현 프리셋과 테스트를 함께 추가한다.

원본 장면 검수는 예외적으로 해당 장면의 일차를 `g.day/progress.day`에 적용한다. 99일차로 고정하면 본편 선택지의 `goto`와 일차 조건이 틀어지기 때문이다. QA 런처의 `ui.day=99`와 독립 진행 객체는 유지하며 본편 carry에 합치지 않는다.

검증: `test-bar-qa-dialogue-ui.cjs`, `test-bar-qa-presets-ui.cjs` (`ui` 묶음). 실제 시작 버튼·홀드 선택·전체 메뉴 도달성·돌아가기, 코스터 3조합 제조·제공 완주, 선택지 효과·알림, 12명 목록/단계, 회상 복귀, 원본 테이블·본편 상태 격리, 좁은 화면을 검사한다.

## 일반 손님 랜덤 외형

단골의 `enter`도 `arrivalAt`·`arrivalDuration`을 기록하고 0.65초 페이드가 완료된 후 다음 대본 단계로 진행한다. 2인 동시 입장은 함께 완료한 뒤 진행하며 코스터·주문 트리거의 대본상 순서는 유지한다. `entrance: seated`는 이미 착석한 장면이므로 새 페이드나 대기 시간을 추가하지 않는다. 일반/단골 모두 표시를 처음 그린 시점이 아니라 실제 입장 시각으로 페이드 진행률을 계산한다. 검증: `test-regular-arrival-speech.cjs`.

일반 손님의 첫 인사는 입장 페이드 0.65초가 끝난 뒤 시작한다. `spawn`의 `arrivalAt`·`arrivalDuration`을 화면의 투명도와 대사 표시/타이핑이 함께 사용한다. 입장 중에는 대사 글자 수와 유지 시간을 진행하지 않으며 말풍선도 숨긴다. 완료 후 실제 타이핑에 맞춰 입이 움직인다. 속도 배율과 별개인 `realTime` 기준이고 일시정지 중에는 함께 정지한다. 기존 비집중 좌석의 자동 진행과 인내심 규칙은 유지한다. 검증: `test-guest-arrival-speech-ui.cjs`.

시뮬레이터 상단 **손님 외형** 탭은 실제 `appearance(gender)` 생성기를 사용한다. 여성/남성을 전환하고 랜덤 재생성 또는 파츠 썸네일을 직접 선택할 수 있다. 왼쪽은 합성 결과와 선택 파일명, 오른쪽은 실제 리소스 후보와 선택 표시다. 성별별 마지막 조합은 탭 안에서 유지하며 게임 손님·대본·주문 상태에는 반영하지 않는다. 정적 파츠 확인 화면이며 대사 애니메이션 검수는 바 QA에서 한다. `appearanceParts`와 `appearanceAllowed`를 게임과 공유해 민소매 전용 팔 밴드 제약도 동일하다. 구현: `src/dev/qa/guest-appearance.js`, 검증: `test-guest-appearance-tab-ui.cjs`.

외형 추첨은 일차/주문용 고정 seed와 분리된 `appearanceRng`(기본 `Math.random`)를 사용한다. 같은 일차·seed로 재시작해도 남녀와 파츠가 새로 추첨된다. 검수에서만 `reset` 설정의 `appearanceRng`로 고정 난수 함수를 넣을 수 있다.

웹 시뮬레이터의 영업 설정 → 시작 구간 → **일반 손님만 · 무한 영업**은 `endless-general` 모드다. 선택한 일차의 제조 가능한 칵테일 범위로 무작위 주문하며 성격·외형을 매 방문 새로 정한다. 대기·코스터·제조·제공·퇴장과 재입장 간격은 기존 일반 손님 규칙을 사용한다. 다음 손님 한 명만 예약해 대기열이 무한히 늘어나지 않으며, 단골 대사·일일 정산으로 자동 전환하지 않는다. QA 99에서도 별도 QA 대화를 시작하지 않는다. 설정 화면으로 돌아가 다른 모드를 시작하면 무한 영업이 해제된다. 본편의 유한 일반 손님 흐름과 CSV는 바꾸지 않는다. 검증: `test-endless-general.cjs`.

일반 손님은 `guest-service.js:spawn`에서 방문마다 한 번 `appearance()`를 호출한다. `runtime-assets.json`에 등록된 `01.ArtResources/01.Characters/01.Bar/09.Customers/`의 정적 파츠만 추첨하며 첨부 HTML의 내장 이미지는 사용하지 않는다. 남녀 각각 몸체 1·상의 3·눈썹 6·눈 4·입 3·머리 2종, 여성 액세서리 3종, 남성 액세서리 2종과 사이버웨어 3종을 사용한다. 액세서리 슬롯은 없음 또는 한 개다. 성별은 50%, 각 슬롯의 유효 후보는 균등 추첨한다. 랜덤이므로 서로 다른 손님에게 같은 외형이 나올 수 있다.

겹침은 몸체 → 상의 → 액세서리 → 눈썹 → 눈 → 입 → 머리 순서다. 실제 남성 `Acc_1`은 목걸이, `Acc_2`는 팔 밴드이며 밴드와 남성 `cyberware_1`·`cyberware_3`는 민소매 `top_3`에만 허용한다. 다른 상의로 변경하면 해당 파츠를 해제하고 선택을 막는다. `cyberware_2`는 이 제한을 받지 않는다. 참고 HTML의 파츠 번호나 구형 CSV 의상 번호를 그대로 대응시키지 않는다. CSV `guest_parts`의 46개 실제 파츠와 `guest_exclusions`의 6개 금지 쌍을 게임·외형 탭이 공유한다. `id`는 실제 이미지 등록 키이고 게임 인물 ID가 아니다. 엔진 원본은 미수정이므로 일반 손님 CSV 3개는 웹이 최신이다. 세부 규칙·엔진 전달 방법은 루트 README의 일반 손님 외형 CSV 항목을 따른다.

외형은 해당 손님 객체에 저장돼 대사·재주문·좌석 초점 전환 중 다시 추첨하지 않는다. 기존 눈·입 애니메이션은 동일 번호 시트가 있을 때만 적용하고, 시트가 없는 눈 4는 선택된 정적 그림을 유지한다. 남녀 입 파츠는 대응 말하기 시트가 있는 1~3번만 사용하며 4·5번은 원본 이미지 보존만 하고 후보에서 제외한다. 단골 외형·주문·정산 규칙은 변경하지 않는다. 검증: `test-guest-random-appearance.cjs`, `test_speech_ui.cjs`.

눈 애니메이션 시트는 눈뿐 아니라 불투명한 얼굴 윗부분을 포함하므로 실제 렌더에서는 해당 시트 뒤에 눈썹을 그린다. 머리카락은 여전히 마지막이다. 정적 파츠의 합성 순서를 애니메이션 시트에 그대로 적용하면 눈썹이 피부에 가려지므로 주의한다.

## 톰 대화 애니메이션

`bar-guest-art.js`는 톰의 기존 4프레임 대기와 2026-10-31 제공 대화 시트를 등록합니다. 눈·눈썹·얼굴 윗부분은 제공 파일과 기존 원본이 바이트까지 같아 공용으로 사용하고, 새 몸통·입은 `assets/characters/tom/talk/`에 원본 그대로 보존합니다. `bar-views.js`의 공통 규칙에 따라 몸은 1.6초 주기를 유지하며 입만 타이핑 중 0.9초 주기로 재생합니다. 입의 프레임별 세로 이동 `[0,1,1,-1]`을 현재 몸 프레임에 맞춰 보정합니다. 완독·화자 전환 시 기존 대기 포즈로 복귀하며, 551×530 캔버스와 테이블 기준 420은 바꾸지 않습니다. 본편·시뮬레이터·QA는 같은 등록부를 사용합니다.

## 본편 필터 구현

본편과 도구의 포함/제외 목록은 [본편 범위](../gameplay/README.md#본편과-도구의-경계)를 따릅니다. `campaign-engine.js`의 `Session.install`은 원래 테이블 참조를 보관하고 본편 세션에서만 필터링합니다. `uninstall`은 참조를 복원합니다. 검증: `test-long-island-main-excluded-ui.cjs`.

`restoration-notices.js`의 `LunaRestorationNotices.check`가 실제 거래 뒤 호출됩니다. 목표 ID는 `old_fashioned_materials`, 레시피 팝업은 `johnnyUnlock`입니다. 목표와 실제 해금의 차이는 [바 영업과 제조](../gameplay/README.md#바-영업과-제조)를 따릅니다. 검증: `test-restoration-notices.cjs`, `test-restoration-notices-ui.cjs`.

## 시뮬레이터 와인 개봉

기믹 미니게임 목록의 **와인 개봉 → 버전 선택**에서만 실행합니다. 사용자 `2버전.html`은 버전 1(호일·스크류·뽑기), `4버전.html`은 버전 2(중앙 맞추기·기울기·2단 지렛대·린넨 포함)에 대응합니다. 본편 큐·레시피·CSV·저장 데이터에는 연결하지 않습니다. `minigames.js`의 기본 `KINDS`/`startMinigame` 계약도 유지합니다.

각 버전은 별도 문서에서 동작하고 공통 `session.js`가 이미지 준비, 활성 시간 기준 지연 작업, 재시작 취소, Esc/포커스 이탈 일시정지, 드래그 해제, 소리 및 종료를 담당합니다. 상위 화면은 출처와 iframe 창을 확인한 메시지로 버전 선택/목록 복귀만 받습니다. 16:9 검정 레터박스를 유지하고 원본 2184×1164 조작 좌표는 렌더·포인터에 동일 변환을 적용합니다. 병은 기존 `item_red_wine` 원본을 등비 확대하고, 오프너는 제공 HTML의 동일 PNG를 바이트 그대로 추출했습니다. `resources.json`에 출처를 기록했습니다. `test-wine-practice-ui.cjs`는 두 버전 실제 포인터 완주·실패·재시작 타이머·일시정지·화면 비율·진행 데이터 보존을 검사하며 `craft` 묶음에 포함됩니다.

## 따르기 종료 잠금

따르기·채우기의 종료 가능 여부는 `pour-fluid.js`의 `Simulation.canFinish`가 공유한다. 입력을 놓고 각도가 정확히 0도로 복귀하며 병 입구 위치가 원점에서 0.1픽셀 이내여야 한다. `pour-view.js`가 매 프레임 버튼 잠금을 갱신하고, `craft-flow.js`의 `endGimmick`도 같은 조건으로 Enter·직접 호출을 차단한다. 복귀 중 입력은 보류/예약하지 않는다. 승인 후의 방울 정리·완료 피드백은 기존 물리 완료 경로를 유지한다. 검증: `test-pour-finish-lock.cjs`, `test-pour-finish-lock-ui.cjs` (`craft` 묶음).

## 제조 시계 구현

`bar-views.js`의 `craftTimer()`는 한 제조 시도의 `craft.elapsed`를 모든 제조 화면에 표시합니다. `gimmick.elapsed`는 단계별 동작·리듬 계산용입니다. 합산/제외 규칙은 [바 영업과 제조](../gameplay/README.md#바-영업과-제조)에 있습니다. 검증: `test-craft-clock.cjs`, `test-craft-clock-ui.cjs` (`craft` 묶음).

## 재화 알림

바·제조·외부·검수용 재화 알림은 `shared/ui/currency-view.js`와 `currency-view.css`를 공유합니다. 등록된 `assets.money` (`assets/01.ArtResources/05.UI/01.Shared/01.MainScreen/IMG_money.png`)는 제공된 `IMG_money.png`와 바이트까지 동일한 원본이며 아이콘과 배경을 한 장으로 사용합니다. 542:108 비율을 유지하고 기존 절반 크기·우측 상단 위치·증감 타이밍은 유지합니다. 별도 SVG 동전이나 둥근 테두리는 덧씌우지 않습니다. 큰 금액은 글자 수에 따라 숫자만 축소합니다. 외부의 증분 갱신에서도 `--currency-digits`를 동기화합니다. 공통 사전 로딩 목록과 리소스 검수 등록 키는 기존 `money`를 그대로 사용합니다.
