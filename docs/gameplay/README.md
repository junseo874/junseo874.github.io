# 본편 구현 확정 기준

기준일: 2026-10-26. 대상: 이 저장소의 `/bar-playtest/`에서 **새 게임으로 시작하는 현재 웹 본편**.

**팀 결정: 현재 웹 본편의 정상 플레이 동작을 게임 구현의 확정 기준으로 삼는다.** 엔진 구현은 과거 기획서나 엔진의 예전 동작이 아니라 이 기준선의 진행 순서, 조건, 입력, 대사 분기, 보상과 연출 결과를 따른다. 이것은 “참고용 프로토타입이니 구현자가 임의로 해석해도 된다”는 의미가 아니다.

웹의 JS 구조나 DOM/CSS를 엔진에 그대로 복제할 필요는 없다. 같은 상태와 입력에서 같은 플레이 결과가 나오는 것이 계약이다. 명백한 오류·진행 불능을 발견하면 재현 조건을 기록해 수정할 문제로 다룬다. 오류를 새 게임 규칙으로 확정하거나, 정상 동작을 임의로 개선해 다른 규칙으로 바꾸지 않는다.

## 읽는 순서와 문서 책임

| 문서 | 여기서 확인할 내용 |
| --- | --- |
| **이 문서** | 본편 범위, 공통 입력·진행·거래·연출 규칙. 공통 규칙의 단일 기준 |
| [사건별 흐름](events.md) | NPC·오브젝트별 시작 조건, 분기, 완료 시점, 다시 만났을 때 동작 |
| [데이터와 대화 연결](data-and-dialogue.md) | CSV 구조, 실제 대화 예제, 코드가 실행하는 부분, 수정·검증 순서 |
| [구조 안내](../architecture/README.md) | 구현 파일 위치와 렌더링·리소스 등 웹 기술 세부사항 |
| [테스트 안내](../architecture/testing.md) | 실행 방법, 회귀 검사와 알려진 검사 범위 |

채팅·노션을 읽지 않아도 위 순서로 기준과 구현 위치를 찾을 수 있어야 한다. `docs/history/`의 예전 설명과 소스의 오래된 주석은 현재 규칙을 덮어쓰지 않는다. 이 문서 묶음과 실행 결과가 다르면 **같은 커밋의 새 게임에서 재현하고 차이를 보고**한다. 문서만 믿고 본편 동작을 임의로 바꾸지 않는다.

새 변경을 확정하면 공통 규칙은 이 파일, 사건별 예외는 `events.md`, 데이터 사용법은 `data-and-dialogue.md`의 해당 위치를 수정한다. 다른 README에 규칙 사본을 늘리지 말고 링크한다. 수치·전체 대사·전체 레시피는 원본 데이터/코드가 소유하고 문서에 별도 사본으로 관리하지 않는다.

## 본편과 도구의 경계

| 구분 | 본편 구현 기준에 포함되는가 |
| --- | --- |
| 새 게임 → 0~3일차 본편 → 현재 종료 화면 | 포함 |
| 본편에서 실제 도달하는 선택형 NPC·집 오브젝트·대화·제조 | 포함 |
| 개발자 모드, P 패널, 99일차, 일차 점프, QA 재생 | 검수 도구. 상태를 강제로 만드는 기능을 본편 규칙으로 이식하지 않음 |
| 리소스 확인·컷씬 확인·데이터 확인 탭 | 조회/독립 재생 도구. 목록에 있다고 본편에 등장하는 것은 아님 |
| 포트 작업장 `workshop` 컷씬 | 확인 탭 전용. 본편 휴식에서는 재생하지 않음 |
| 독립 와인 개봉 버전 1·2 | 시뮬레이터 전용. 본편 제조 큐에 추가하지 않음 |
| 롱아일랜드 `long_island` | 본편 레시피·주문·제조·해금 목록에서 제외. 개발자용 원본은 보존 |
| 바카디, 쿠앵트로 별도 재료, BD 판매상 | 현재 본편에 되살리지 않음. 쿠앵트로 역할은 `triple_sec`로 통합 |
| 앱 종료 후 저장·불러오기 | 현재 미구현. 세션 상태 복사나 설정 저장을 게임 세이브로 해석하지 않음 |

본편 여부는 파일의 존재가 아니라 `campaign-engine.js`의 본편 세션과 실제 진입 경로로 판단한다. 개발자 모드가 A/B 연출이나 옛 데이터를 보여줘도 새 게임의 기본 본편 경로보다 우선하지 않는다.

## 전체 진행과 상태

기본 순서:

```text
새 게임
  → 0일차 집 도입부
  → 출근길 탐색 → 바 진입
  → 바 이야기·주문·제조·제공 → 영업 정산
  → 퇴근길 탐색 → 집에서 휴식
  → 미확인 부비 첫 휴식 반응이 있으면 먼저 재생
  → 해당 밤 테라스 대화, 없으면 수면 연출
  → 필요한 조니 기억 처리 → 다음 날 기상·출근
  → 3일차 마감 후 현재 종료 화면
```

- 출퇴근은 `flow: in / out`, 위치는 `scene: street / home`, 층은 `level`로 구분한다. 일차만 보고 NPC를 활성화하지 않는다.
- 부비 입양과 엘리베이터 수리는 선택형이며 하지 않아도 일차 진행을 막지 않는다. 이미 시작한 상태와 보상 기록은 일차가 바뀌어도 이어간다.
- **2일차 귀가·마감에는 별도 올드패션드 진행 조건이 있다.** `dayEndRequirements` / `johnnyMissing`의 재료·기억 조건을 따른다. 모든 선택형 사건에 이 제한을 일반화하지 않는다.
- 2일차 귀가 검사에서는 와일드 독·비터스 보유를 확인하고, 마감 연결에서는 아직 보지 않은 조니 기억을 재생한다. 기억 확인 기록은 `campaign_observation`, 3일차 각설탕 수령은 `day3_sugar_received`이다. 개발자 일차 점프의 선행조건 보정은 실제 획득 사건이 아니다.
- `barGame.progress`가 현재 재화·보유·플래그 등을 소유한다. `session.carry`는 바/거리/다음 일차 사이에 전달하는 실행 중 복사본이며 영구 저장 파일이 아니다.
- 바 시작 시 `session.checkpoint`를 만들어 해당 영업 재시도에 사용한다. 앱을 종료한 뒤 돌아오는 저장 기능과 다르다.
- 본편 진입은 `campaign.js`, 일차·정산·carry 연결은 `campaign-engine.js`, 바 진행은 `core.js`, 거리 진행은 `outside.js`가 소유한다.

## 상호작용과 입력

| 상황 | 확정 동작 |
| --- | --- |
| 외부·집 상호작용 | 현재 방/층에서 유효한 가까운 대상에 E. 윤곽선·하단 문구·실행 대상은 일치해야 함 |
| 대상이 겹침 | 거리 우선, 동률 우선순위 및 작은 이동의 유지 여유 적용. 선택 대상이 프레임마다 떨리지 않음 |
| 물음표 | **전면 미표시**. 과거 방문/열람 기록 코드는 남아 있어도 표식을 다시 만들지 않음 |
| 직접 대사 타이핑 중 확정 | 현재 줄 전체 표시. 다음 새 입력으로 다음 줄 진행 |
| 외부 선택지 등장 | 최초 500ms 동안 E·Enter·Space·클릭 확정 금지. 이동/호버는 허용, 입력을 나중에 자동 실행하지 않음 |
| 바 대화 선택지 | 현재의 **0.5초 연속 홀드** 유지. 외부처럼 별도 500ms 등장 지연을 더하지 않음 |
| 외부 조건 부족 선택지 | 포커스 이동 가능. 확정 시 거래/분기는 실행하지 않고 빨간 배경·흔들림·글리치와 짧은 불가 사유 표시. 다른 선택으로 이동하면 원문 복구 |
| 바 조건 부족 선택지 | 비활성화 + 짧은 조건 설명. 외부의 빨간 거부 연출과 구분 |
| 비밀 선택지 | 해금 전 `???`, 이유도 내용을 누설하지 않음. 미출시 항목을 조건 부족 항목처럼 노출하지 않음 |
| Esc | 취소 가능한 최상위 화면 하나를 닫음. 닫을 화면이 없을 때 설정. 필수 사건에 임의 취소 경로를 추가하지 않음 |
| 조작 안내 | 게임 화면의 별도 `?` 도움말 버튼은 표시하지 않는다. Esc 설정창의 ‘조작 안내’ 탭에서 확인한다. |
| 외부 선택지와 말풍선 | 외부에서만 선택지 행의 대사가 비어 있으면 같은 대화의 직전 대사·화자·강조를 유지한다. 이전 대사도 없으면 선택지만 표시하고 빈 말풍선은 그리지 않는다. 다른 상호작용의 대사를 가져오지 않는다. |
| 바 내부 선택지와 말풍선 | 직전 대사를 선택지에 유지하거나 다시 표시하지 않는다. 기존처럼 대사를 마치면 말풍선을 닫고 선택지만 표시한다. |
| 설정·포커스 이탈 | 게임 조작/진행을 멈추고 눌린 키·드래그·홀드 정리. 복귀 후 현재 상태에서 조작 재개 |
| 외부 대사·컷씬 | 전체 건너뛰기는 미제공하되 **TV 다큐만 Space 2초 연속 홀드로 스킵 가능**(본편·컷씬 확인 공통). 중간에 떼거나 설정을 열면 홀드 취소. 본편 스킵 후 시청 완료로 처리하고 집 조작 복귀. 정상 다음 줄 입력과 스킵은 별개 |
| 포인터 | 자동 연출에서는 숨김. 수동 대사·선택지·설정에서는 표시 |
| 웹 기본 동작 | 플레이 화면의 텍스트 선택·이미지 기본 드래그 등 방지. Windows F11 전체화면은 허용 |

상호작용 문구는 대상의 행동을 표시한다. 포스터·책·침대 등 조사, 사람 대화, TV 보기, 소파 휴식, 엘리베이터 작동, 안쪽 문 나가기/복도 문 들어가기를 구분한다. 실제 대상별 문구는 `outside.js`의 `interactionLabel`을 사용한다.

바 홀드에 관한 예전 D01 변경 논의는 별개이며, **이 인수인계 기준선에서는 현재 동작인 0.5초 홀드가 기준**이다. 새 홀드 정책을 추정해 구현하지 않는다.

## 대화와 사건 실행

- 단골 정보 목록은 크리스·포트·아일리·부비·개시바·삼호·톰·송하루·유선하·히나·리오스·볼츠 12명이다. 각 인물의 `_met` 등록 플래그가 있어야 이름·상세를 열 수 있다. 아직 등장하지 않은 인물을 목록에 추가했다고 본편에서 자동 등록하지 않는다. 익명 일반 손님은 영구 단골 목록에서 제외한다. 이미지/정보 원고가 없는 항목은 준비 중으로 남긴다. QA의 전원 해금·3단계 강제 표시는 본편 규칙이 아니다.

- 바 서비스 패널의 **단골 손님 정보 → 대화 기록** 또는 Y로 현재 영업의 바 대화를 왼쪽 패널에서 확인한다. 완료된 대사는 시간순으로, 현재 줄은 이미 표시된 글자까지만 보여준다. 열면 최근 기록으로 이동하며 스크롤로 이전 기록을 확인한다. 기록 열람 중에는 진행이 멈추고 Esc·닫기·Y로 복귀한다. 익명 화자는 당시의 `???`를 유지한다. 현재 기록 범위는 바의 해당 영업이며 일차/영업 초기화 시 비워진다. 외부·컷씬 통합 기록이나 영구 저장을 의미하지 않는다.
- 직접 NPC 대사는 기본 수동 진행. 주변 잡담·TV 방송은 자동 진행. 컷씬은 해당 연출의 자동/수동 대기 지정에 따른다. “컷씬이므로 전부 자동”으로 만들지 않는다.
- 직접 대화 중 주변 잡담의 표시·진행을 멈춘다. 종료 후 거리 안이면 기존 줄과 타이핑 위치에서 재개한다. 자동 반복에는 공통 4초 간격이 있고, 각 사건의 1회/거리 재진입 조건도 함께 적용한다.
- 주 사건은 동시에 하나만 실행한다. 강제 근접 사건은 조건과 **경계 진입**을 확인해 대기열에 넣고, 시작 직전에 다시 검사한다. 범위를 벗어나 조건을 잃은 대기 항목은 제거한다.
- 현재 우선순위는 1일차 복도 불량배 10, 2일차 불량배/3일차 계약 20, 밀수 거래 30, 삼호 출근 대화 40이다. 진행 중인 사건을 새 사건이 가로채지 않는다.
- 일반 NPC 대화에 임의 카메라 이동·줌을 추가하지 않는다. 강제 사건과 승인된 컷씬은 각 모듈의 진입/퇴장 연출을 따른다.
- 말풍선 폭·여백을 공통화하고 화면 밖으로 넘지 않게 보정한다. 꼬리는 실제 화자를 가리킨다. 선택·포커스 때문에 테두리가 발광하지 않는다.
- NPC의 발·머리·말풍선 기준점은 같은 포즈를 사용한다. 이동 방향과 시선, 정지/대화 상태의 Idle을 일관되게 유지한다. 갱단의 대화 전/중 시선 예외는 [사건별 흐름](events.md)에 있다.

## 거래와 완료 기록

1. 표시된 조건과 **확정 시점의 조건을 모두 검사**한다. UI가 활성화되어 있었다는 이유로 무조건 실행하지 않는다.
2. 거래는 차감·약속/지급 기록을 함께 갱신한다. 같은 입력이나 중단 후 재진입으로 돈을 두 번 차감하지 않는다.
3. 지급과 연출 완료는 다른 순간일 수 있다. 사건별 `pending / paid / received / done`을 하나로 합치지 않는다.
4. 열람으로 얻는 정보는 해당 흐름에서 정한 확인/완료 시점에 기록한다. 대화 UI를 열었다는 사실만으로 모든 정보를 해금하지 않는다.
5. 완료 콜백은 정상 종료에만 호출한다. 취소·QA 재생을 본편 완료로 처리하지 않는다.

인벤토리 아이템은 **수량 소비가 아닌 보유 해금**으로 취급한다. 현재 호환 데이터의 숫자 `1` 또는 양수는 보유를 뜻하며, 참치캔·기어 사용 뒤에도 해금은 유지한다. 이것은 칵테일 레시피의 `45ml`, 각설탕 `1개` 같은 제조량을 없앤다는 뜻이 아니다. 재화는 실제로 차감하며 중복 구매·중복 보상은 플래그로 막는다.

## 바 영업과 제조

- 이야기 단계와 일반 손님 단계, 주문, 레시피 선택, 재료 준비, 기믹 큐, 제공, 판정, 정산을 구분한다. 대사만 끝났다고 주문/기믹까지 완료 처리하지 않는다.
- 일반 손님은 입장할 때마다 비어 있는 1·2·3번 좌석(L/M/R) 중 하나를 동일 확률로 추첨한다. 좌측 우선 순서나 일차별 고정 시드를 사용하지 않으며, 손님이 있거나 퇴장 후 정리 중인 좌석은 제외한다. 단골의 대본 지정 좌석은 유지한다.
- 일반 손님이 입장해도 현재 선택 좌석과 카메라를 유지한다. 첫 손님이나 전원 퇴장 후 다음 손님도 자동으로 바라보지 않으며, 플레이어가 A/D 또는 좌석 선택으로 직접 확인한다. 이야기 연출과 제조 후 복귀 카메라는 별도 규칙을 유지한다.
- 일반 손님은 플레이어가 다른 좌석을 보거나 카메라 이동·코스터 드래그로 말풍선이 숨겨져도 주문 대사 → 제공 후 반응 → 정산 → 재주문/퇴장이 자동 진행된다. 대사를 끝까지 보는 것은 진행·정산 조건이 아니다. 판매·팁·환불은 기존 판정대로 주문당 한 번 적용하며, 미제공 시간 초과는 임의로 돈을 지급/차감하지 않는다. 설정·기록 등 일시정지와 제조 화면에서 일반 영업 시간이 멈추는 규칙은 유지한다. 보지 않은 일반 손님 대사는 기록에 추가하지 않고, 일부만 본 줄은 표시됐던 부분까지만 남긴다.
- 바 우측 상단의 단골 이름·주문 칵테일 요약 배지는 표시하지 않는다. 실제 주문 데이터와 제조·제공·판정은 유지한다.
- 톰의 ‘새로운 인물!’ 알림은 입장이나 ‘톰이야.’가 아니라 **‘톰이라고. 톰 거너. 내 이름이야. ‘당신’ 말고 그렇게 불러.’ 대사 시작 시점**에 한 번 표시한다. CSV 대사 ID `campaign_d1_bar_77`을 기준으로 `story-notices.js`가 연결하며, `tom_introduction_notified`로 중복 방지한다. `tom_met` 만남 기록과 기존 `tom_name_known` 이름 표시 시점은 유지한다.
- 주문·해금은 `scenes`, `steps`, `cocktails`, `shelf_items`, `recipes`와 현재 진행 상태를 함께 사용한다. ID가 데이터에 있어도 본편 세션 필터나 해금 조건을 통과해야 노출된다.
- `recipes`의 재료·순서·양·도구와 `core.js`가 만드는 실제 기믹 큐를 따른다. 숫자와 배점을 문서에 재작성하지 않고 원본 테이블을 읽는다.
- 한 제조 시도에서 `craft.elapsed`를 공유한다. 따르기를 두 번 하고 쉐이킹을 하면 세 단계의 유효 수행시간이 누적된다. **개봉 기믹은 채점 시간에서 제외**한다.
- 첫 조작 전, 튜토리얼·설정·포커스 이탈 일시정지, 완료 피드백과 단계 전환은 제외한다. 기믹 시작 뒤 조작하지 않고 머무른 유효 시간은 포함한다. 단계용 `gimmick.elapsed`와 혼동하지 않는다.
- 스터·쉐이킹은 목표 달성 직후 바로 넘어가지 않고 완료 피드백 뒤 다음 단계/제공으로 이어진다. 정확한 시간은 해당 구현과 `test-mix-completion*`을 따른다.
- 기믹 화면에 공통 조기 종료용 ‘현재 기믹 마치기’ 버튼을 표시하지 않는다. 스터·쉐이킹 연습의 동일한 ‘결과 보기’ 버튼도 제거하며 정상 완료 후 자동 이동한다. 따르기 종료·병따기 완료 확인은 별도 진행 조작으로 유지한다.
- 코스터·칵테일 드래그는 커서 대신 집은 오브젝트를 표시한다. 제공 판정 영역은 보이는 영역보다 넉넉하게 설정되어 있으므로 보이는 그림 크기와 판정 범위를 동일시하지 않는다.
- 점수·등급·가격·정산은 `settings/`와 `craft/` 데이터 및 실제 판정 함수를 함께 본다. 본편 주문 재시도 판단은 `Session.problems`도 적용한다.
- 올드패션드 재료 2종 획득 목표와 실제 레시피 해금은 별개다. 실제 제조는 3일차·조니 기억·각설탕·`johnny_recipe_unlocked` 흐름을 따른다. 재료 둘만 있다고 미리 제조시키지 않는다.

## 날씨와 환경음

| 일차 | 출근길 | 퇴근길 |
| --- | --- | --- |
| 0 | 비 없음 | 비 |
| 1 | 비 | 비 |
| 2 | 비 | 비 없음 |
| 3 | 비 | 비 |

원본 판정은 `outside-rain.js`의 `wet`이다. 집은 같은 날씨에 맞는 실내 빗소리, 거리는 도시음과 실외 빗소리, 테라스는 실제 표시 중인 장면의 출퇴근 상태를 사용한다. 숨겨진 집 화면의 환경음으로 테라스를 판단하지 않는다.

비 오는 집에서는 문 쪽이 작고 창문/테라스 쪽으로 갈수록 실내 빗소리가 커진다. 탭 이동만으로 환경음 재생 위치를 처음으로 되돌리지 않는다. 장면 이탈·음량 변경에 의한 감쇠/종료는 별개이며 브라우저 자동재생 제한으로 최초 사용자 입력이 필요할 수 있다.

## 장면 전환과 리소스

- 다음 장면의 필수 캐릭터·대사·UI 리소스를 준비한 뒤 공개한다. 실패 시 로딩 오류/재시도 경로를 사용하고 임의의 첫 손님·첫 재료로 바꾸지 않는다.
- 이전 장면의 말풍선·입력·임시 연출을 정리한다. 암전·카메라·캐릭터 배치가 끝나기 전에 조작을 돌려주지 않는다.
- 카메라 고정 컷씬, 엘리베이터 이동 중에는 플레이어가 연출 범위를 벗어나 배경을 움직이거나 난간 밖으로 나갈 수 없게 한다.
- 테라스 진입은 수평 이동과 원경 패럴랙스이며 애니메이션 줌인/줌아웃은 없다. 고정 오버스캔 배율과 시간에 따른 줌을 구분한다.
- 리소스의 표시 크기·피벗·레이어·마스크는 [구조 안내](../architecture/README.md) 및 실제 표현 데이터의 값이 기준이다. 엔진 이식 시 웹 좌표를 그대로 쓰기보다 화면에서의 상대 위치와 가림 결과를 맞춘다.

## 확인과 전달

```sh
python3 serve.py
node tools/check-structure.cjs
node tools/check-site.cjs
node tools/build-shared-data.cjs
node tools/run-tests.cjs smoke
```

그다음 변경 영역별로 `ui`, `outside`, `cinema`, `craft`, `data` 묶음을 실행한다. 엔진에서는 같은 입력·조건·결과를 검수하되 웹 테스트가 엔진 검증을 대신한다고 보지 않는다. 전체 옛 테스트의 상태는 [테스트 안내](../architecture/testing.md)를 따른다.

팀에 전달할 때는 문서·CSV·생성 데이터·구현·테스트를 **같은 커밋**으로 제공한다. 미커밋 로컬 변경은 GitHub 클론에 포함되지 않는다. 과거 커밋에 이 문서를 붙여 최신 동작이라고 부르지 않는다. 이후 규칙을 변경할 때도 해당 문서와 테스트를 함께 갱신한다.
