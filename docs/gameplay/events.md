# 본편 사건과 대화 흐름

[본편 구현 확정 기준으로 돌아가기](README.md) · [데이터 연결 방법](data-and-dialogue.md)

현재 새 게임의 실제 흐름을 기준으로 한다. 아래의 “기록/유지”는 실행 중 일차·장면 간 상태 유지이며 앱 종료 후 저장을 뜻하지 않는다. 전체 대사는 복사하지 않고 CSV와 실행 키로 찾는다. 이후 새 콘텐츠는 해당 사건의 항목을 갱신한다.

## 부비

**시작:** 2일차 출근부터 집 앞 복도. 아직 입양하지 않았다면 이후 일차에도 남는다.

1. 처음 가까이 가면 박스가 한 번 흔들리고 `boobi_box_shaken`을 기록한다. 이 접근만으로 입양 대화가 시작되지는 않는다.
2. 박스에 E → 구멍의 눈/등장 연출 → 위로 튀어나와 옆 박스에 착지 → `boobi_revealed`. **여기서 끝나고 조작 복귀**한다.
3. 부비에 별도로 E → “야옹”과 쓰다듬기/참치캔 주기/취소 선택.
4. 참치캔이 없으면 불가 연출만 표시. 가지고 있으면 `boobi_feeding_pending`을 기록하고 먹기 → 루나 대사 → 옆집 주민 접근·대사·퇴장 → 암전 → 집 이동으로 이어진다.
5. 입양 전환에서 `boobi_adopted`를 기록하고 pending을 해제한다. 집 소파 위 부비와 루나의 마지막 대사 뒤 종료한다. 참치캔 보유 해금은 소비하지 않는다.
6. 입양 후 처음 휴식하면 `neighborhood/rest`를 먼저 실행한다. 암전 → TV 오른쪽에 크리스 고정 배치 → 고정 배율의 좌→우 카메라 이동 → 대사. 정상 종료 때 `boobi_rest_seen`을 기록한다.
7. 이어서 해당 밤 테라스/수면과 일차 마감으로 돌아간다. `workshop`은 끼워 넣지 않는다. 입양 직후 휴식하지 않아도 첫 반응은 다음 휴식까지 남는다.

집의 부비는 “냐옹” → 쓰다듬기/취소. 쓰다듬기는 눈·꼬리·하트 반응 후 복귀하며 돈이나 첫 휴식 상태를 변경하지 않는다. 이 사건의 미연결 사운드 큐는 기본 무음이며 임의 음원을 추가하지 않는다.

## 수리공과 엘리베이터

**시작:** 1일차 출근부터 엘리베이터 하단 오른쪽. 수리하지 않으면 이후에도 남는다.

- 첫 E → 인사/불평 → 대화한다/무시한다. 설명을 정상적으로 마치면 `repairman_met`.
- 재상호작용 → 기어 부품/400원/취소. 보유/돈 조건을 확정 시 다시 검사한다. **포트에게 기어를 얻는 본편 대화는 아직 없다.** 데이터에 기어가 있다고 해당 획득 사건을 새로 만들지 않는다.
- 거래 확정 시 400원 경로는 돈을 차감하고, 두 경로 모두 `elevator_repair_paid`를 기록한다. 기어는 보유 해금을 소비하지 않는다.
- `repairPaid` 대사 → `repair` 액션 → 암전 중 `elevator_repaired` → 마지막 수리 완료 대사.
- 마지막 대화 종료 시 `엘레베이터 수리!` 목표 달성 알림을 한 번 표시하고 수리공이 퇴장한다. paid 상태로 중단된 경우 다시 차감하지 않고 완료 흐름으로 이어간다.

엘리베이터는 E 즉시 이동하지 않는다. 하단은 올라간다/취소, 상단은 내려간다/취소. 수리 후에는 **빠른 이동이 첫 번째**, 일반 이동이 두 번째, 취소가 마지막이다. 빠른 이동은 암전 후 반대 층으로 이동하며 본편 귀가 조건 검사도 통과해야 한다. 일반 이동 중에는 난간 밖 이동을 허용하지 않는다.

## 모닥불 갱단

**시작:** 0일차 퇴근부터. 경비 앞 경계는 이동만 막으며 닿았다고 강제로 대사를 시작하지 않는다. E로 대화한다.

- 2일차 출근 전에는 통행을 허가하지 않는다.
- 2일차 출근부터 술 질문/자리를 뜬다. `guardPass`의 와일드 독 질문과 중앙 남자 안내를 **끝까지 마친 뒤** `gang_pass_granted`를 기록해 경계를 푼다.
- 중앙 보스 첫 대화는 `bossIntro`, 이후는 `bossRepeat`. `boss-met` 액션이 `gang_boss_met`을 기록한다.
- 기다린다 → 거래 없이 종료. 수리 완료 또는 500원 → 조건을 재확인한 뒤 해당 거래 대사로 진행한다.
- 돈은 확정 시 차감하고 `gang_wild_dog_paid`, 수리 경로는 `gang_wild_dog_repair_promised`를 기록한다. 첫 거래/재방문 대사는 `gang_wild_dog_repeat_deal`로 구분한다.
- `wild-dog-grant` 액션에서 와일드 독 지급·획득 알림·`gang_wild_dog_received`를 처리하고 거래 대기 플래그를 지운다. 중단 뒤에는 같은 거래를 이어가며 재차감하지 않는다.
- 이미 받았다면 `bossDone`. 옛 시바견 구매 기록/기존 보유분도 중복 지급 방지에 반영한다.

대화 전에는 모닥불을 중심으로 서로 마주본다. 플레이어 이동만으로 전원이 따라 보지 않는다. 직접 대화의 대상/참여자만 루나를 보고 종료하면 원래 방향으로 돌아간다.

## 시바견 상점

**시작:** 2일차 출근부터 3일차까지, 거리 하단.

```text
첫 만남 설명 또는 재방문 인사
  → 재방문은 한번 볼게요 / 아니요
  → 상품 확인
     → 두 재료 보유 + 아직 학습 전이면 학습·퀴즈
     → 아니면 용돈 조건에 해당할 때 지원 선택
     → 아니면 상품 목록
```

- 상품 목록의 첫 선택은 **구매하지 않는다**. 비터스 300원, 참치캔 50원. 참치캔은 2일차 출근부터, 미보유·부비 미입양일 때 상품 단계에만 나타난다. 인사 선택에 바로 끼워 넣지 않는다.
- 와일드 독은 팔지 않는다. 소지금 부족 시 외부 공통 거부 연출, 이미 산 상품은 재구매시키지 않는다.
- 구매한 물품은 선택지에서 제거한다. 현재 팔 수 있는 물품이 전부 없어지면 재방문 인사·‘한번 볼게요’·빈 상품 목록 대신 ‘이제 팔 거 없어. 꺼져, 시바.’ 대사로 종료한다. 단, 미완료 올드패션드 학습·퀴즈 조건이 충족되면 이 별도 사건은 계속 진행할 수 있다.
- 상품 선택 중 시바견의 ‘…전부 다 보여 주긴 싫고 몇 개만 보여 줄게.’ 대사를 유지한다. 별도의 ‘어떤 걸 살 거야?’ 질문은 사용하지 않는다.
- 구매 확정 시 돈·`shiba_bought_*`·인벤토리를 함께 갱신한다. 이후 대사를 취소해도 구매를 없던 일로 돌리거나 중복 결제하지 않는다.
- 용돈은 상점이 열리는 2일차에 소지금 300원 이하이면서 아직 받지 않은 경우 제안한다. 수락 대사의 `shop-allowance-grant`에서 500원과 `shiba_allowance_received`를 함께 기록한다. 플레이 전체 한 번이며 거절은 지급 완료가 아니다.
- 비터스와 와일드 독을 모두 보유하고 `shiba_old_fashioned_taught`가 없으면 학습/퀴즈. 비터스를 두 번째로 샀다면 구매 답변 뒤, 와일드 독을 나중에 얻었다면 다음 상품 확인에서 시작한다.
- 오답은 다시 설명·퀴즈, 정답은 학습 완료 기록. 퀴즈는 구매 조건이 아니고 추가 차감/아이템 지급이 없다. 이 기록을 실제 올드패션드 제조 해금과 혼동하지 않는다.

## 사기꾼과 근처 행인

**등장:** 0일차 퇴근/1일차 출근 구간. `outside-beggar.js`가 날짜·방문 상태를 판단한다.

- 사기꾼 첫 대화/재방문 대사는 `street_beggar_met`으로 구분한다. 200원 준다/거절/사기꾼 질문의 세 분기다.
- 행인의 경고 대화를 완료해야 `street_beggar_warned`가 생기고 특수 질문이 열린다. 그 전에는 `???`.
- 200원 지급은 차감과 `street_beggar_paid`를 함께 기록한다. 열 배로 돌려준다는 **대사는 보상 지급 명령이 아니다**.
- 지급 대사 후 사기꾼이 떠난다. 행인은 그 거리 방문 동안 지급 후 반응을 볼 수 있지만 이후 재방문에서는 사라진다.
- 행인의 미지급/지급 후 첫 대화와 반복 대화를 별도로 구분한다. 정보를 얻는 완료 시점과 단순 첫 접근을 합치지 않는다.

## 강제 사건과 주변 대화

강제 사건들은 공통 대기열을 거치지만 세부 상태는 각 사건이 소유한다.

| 사건 | 본편 조건과 종료 기록 |
| --- | --- |
| 1일차 복도 불량배 | 1일차 출근, 상층 복도 지정 범위. 지불/거부 선택과 액션, 퇴장·카메라 복귀 후 `day1_thug_done`. 지불은 선택 확정 시 500원 |
| 2일차 불량배 | 2일차 출근, 상층 복도의 고양이 오른쪽 옆집 문 앞. 문 근처에 접근하면 시작하며 고양이·박스 앞에서는 시작하지 않는다. `day2_thug_done` 전 강제 재회, 이후 정보 상호작용은 별도 대상/분기 |
| 밀수 거래 목격 | 1일차 퇴근, 하층 지정 범위. 대화와 카메라 복귀 후 `day1_trade_done` |
| 삼호 출근 | 2·3일차 출근, 하층 삼호 근처. 진입→대사→퇴장→카메라 복귀 후 `day2_samho_done` / `day3_samho_done`, `samho_met` |
| 3일차 계약 | 3일차 퇴근, 지정 인물 근처. 계약 관련 대화 → 밀수업자 퇴장 → 삼호 접근·루나와 대화 → 삼호 퇴장·카메라 복귀 후 `day3_contract_done`. 플레이어 계약 선택지를 임의로 추가하지 않음 |

2일차 불량배 정보 상호작용은 갱/코라테크/크리스 주제 선택 → 50원 지불 확인 → 해당 설명이다. 확정 시 돈을 차감한다. 현재는 해당 정보를 샀다는 영구 해금으로 재방문 가격을 없애지 않으므로 다시 구매하면 다시 50원이 든다. 취소는 대화 종료, 부족하면 공통 불가 연출이다.

이 표의 범위 숫자와 액션 순서는 각 모듈의 `offer`, `choiceView`, `choose`, 액션/완료 함수가 정본이다. 같은 날짜라는 이유로 다른 위치에서도 자동 시작시키지 않는다.

주변 잡담은 주 사건이 아니다. `BackgroundStories`의 독립 채널·거리 조건·완료/재진입 조건을 사용하며 직접 대화 중 멈춘다. 4초 공통 간격이 있다고 모든 1회 잡담을 영구 반복으로 바꾸지 않는다. TV의 자동 방송과 E로 시작하는 TV 컷씬도 서로 다른 흐름이다.

| 시바견 포스터 | 이미지 조사 화면. 이 조사에 개 짖는 소리를 붙이지 않음 |
| 0일차 TV | 처음은 컷씬 직접 진입. 이미 본 상태면 TV를 본다/끈다 선택으로 재시청 제어. 대사 타이핑·입력 대기 중에도 스캔라인/노이즈는 계속 움직이며 장면·대사만 입력을 기다림. 설정·포커스 일시정지는 효과에도 적용하며 복귀 시 이어 재생 |
| 소파 | 휴식 선택과 현재 본편 마감 조건 검사. 부비 첫 반응과 밤 장면 연결은 공통 진행 규칙 참조 |
| 문·바 입구 | 현재 안/밖·출퇴근·일차 조건을 확인해 장면 전환. 이전 말풍선/입력 정리 |

모든 대상에 물음표는 없다. 조사 화면의 나가기 안내도 공통 상호작용 표시를 사용한다. 집 안 부비는 별도 NPC 상호작용이며 소파 휴식 선택과 합치지 않는다.

## 바와 밤 대화의 추적 순서

1. `story/scenes.csv`의 실제 `day / phase / seq / when`과 본편 세션 필터로 진입 장면을 찾는다.
2. 그 장면의 자식 `steps`를 따라간다. `say`뿐 아니라 입장, 선택, 주문, 제조 대기, 캠페인 위임 단계를 함께 읽는다.
3. 선택의 `goto`, 주문의 `arg`, `campaign_*` 위임은 각 실행 담당까지 추적한다. 대사 목록만으로 플레이 순서를 추측하지 않는다.
4. 정산 확정 후 퇴근 carry로 이어지고 집 휴식에서 `playSleepScenes`를 호출한다.
5. 밤 장면 키는 0일차 `night0`, 1일차 `night1`, 2일차 `night2`, 3일차 `ending`이다. 부비 첫 반응이 있으면 그 앞에 들어간다.
6. `workshop`은 본편에서 제외되어 있다. 원본 CSV·검수 카드가 남아 있어도 휴식 뒤 연결하지 않는다.

## 사건 추가 또는 수정 시 반드시 확인할 항목

현재 사건을 바꿀 때 이 항목을 코드/데이터와 함께 명시한다. 빈칸을 임의로 채워 새 규칙을 만들지 않는다.

- 본편 일차·출퇴근·장소·층·접근 범위·선행 플래그
- 자동 시작인지 E 상호작용인지, 주 사건인지 주변 잡담인지
- 대화 source/scene/웹 키, 선택 ID, 조건 부족 시 표현
- 조작 잠금, 카메라, 등장·퇴장, 자동/수동 대기
- 비용 차감, 지급, 정보 획득, 사건 완료 각각의 정확한 시점
- 취소·설정·재진입·다음 일차에서 이어갈 상태와 중복 방지
- 실제 본편에서 재현하는 경로와 회귀 테스트
