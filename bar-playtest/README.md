# L.U.N.A 바 영업 플레이테스트

## 실행

폴더의 **index.html을 Chrome 또는 Edge로 열면 됩니다.** 서버 설치나 npm 설치 없이 실행하도록 만들었습니다. 한글 폰트와 이미지가 모두 폴더에 포함되어 있으므로, 전달할 때는 index.html만 보내지 말고 폴더 전체를 보내세요.

편집 원본: GitHub Pages 저장소의 `bar-playtest/` 폴더. 사이트 로비에서 **바 영업 플레이테스트**로 들어옵니다. **ESC 옵션 → 로비로 돌아가기**로 되돌아갈 수 있습니다.

사이트 로컬 주소: http://127.0.0.1:8123/bar-playtest/ (`python3 serve.py`는 저장소 루트에서 실행). 기존 http://127.0.0.1:8765 주소도 이 폴더를 가리키며 별도의 수정본이 아닙니다.

브라우저 검수 시 `LUNA_TEST_URL=http://127.0.0.1:8123/bar-playtest/`를 지정하면 하위 페이지 경로로 검수합니다. 원본 CSV를 자동 동기화하지 않으며 데이터 재반영은 아래 가져오기 도구를 명시적으로 실행해야 합니다.

### 기믹 미니게임

메인 로비의 **기믹 미니게임** 카드 또는 바 플레이테스트 시작 화면의 같은 이름 탭으로 들어갑니다. 바로가기: `bar-playtest/?mode=minigames`.

- 병따기 / 따르기 / 필업 / 쉐이킹 / 스터 중 하나를 누르면 주문·대사·재료 선택 없이 해당 기믹 한 개만 실행합니다.
- **기존 규칙 / GPT 개선 규칙**을 고를 수 있습니다. 개선 규칙은 편안하게 / 보통 / 도전 난이도도 선택합니다. 실제 영업의 같은 입력·판정·그림을 재사용합니다.
- 예시는 실제 레시피에서 가져옵니다: 병맥주 병따기, 진토닉 진 따르기(1.5 oz)·소다워터 필업(4 oz), 진피즈 쉐이킹, 드라이 마티니 스터. 원본의 목표량이 바뀌면 연습도 그 값을 읽습니다.
- 기존 규칙은 완료 후 **결과 보기**를 누릅니다. 개선 규칙은 병따기·쉐이킹·스터 완료 후 자동으로 결과 화면에 갑니다. 따르기·필업은 양을 조절한 뒤 결과 보기를 누릅니다. 병따기는 열기 전 건너뛰기를 막습니다. 쉐이킹·스터는 시작 후 현재 결과로 끝낼 수 있고, 미실행 횟수도 목표 횟수에 포함되어 점수가 낮아집니다.
- 해당 기믹만 100점 기준으로 평가합니다. 수량은 기존 수량 오차 구간, 병따기는 완료/실패 횟수, 믹스는 성공 비율을 사용합니다. 전체 칵테일의 재료·잔·도구·시간 감점은 적용하지 않습니다.
- 결과에서 **같은 기믹 다시 하기 / 다른 기믹 고르기 / 영업 시작 화면**으로 이동합니다. 우측 상단의 작은 **다른 기믹 선택** 버튼은 진행 중일 때 중단 확인 후 목록으로 돌아갑니다(시작 전에는 바로 복귀). ESC 옵션에서 시간을 멈추고 언어·BGM·병따기 효과음을 조절할 수 있습니다.
- 영업 소지금·목표 보상·단골 진행·읽음 기록·칵테일 최고점에 합산하지 않으며 F2 영업 테스트 도구는 표시하지 않습니다. 미니게임 기록을 새 저장 파일로 만들지 않습니다.
- 검수: `tools/test_minigames.cjs`와 `tools/test_minigames_ui.cjs`. 기존 영업 검수와 별도로 실행합니다.

### 쉐이킹 타격·얼음 연출

- 기존/GPT와 영업/단독 연습 모두 동일한 피드백을 사용합니다. 성공 입력에서 시작하는 기존 4프레임 손동작과 판정 거리·노드 배치·점수·성공 횟수는 변경하지 않았습니다.
- 성공 노드에 작은 파편·확산 링, 판정 범위에 들어온 노드 강조, 이동 표시에 짧은 잔상을 추가했습니다. 캐릭터 화면에만 최대 2.5px 반동과 약한 테두리 빛을 주며, 판정 보드와 노드 좌표는 움직이지 않습니다.
- 성공 입력마다 선택한 실제 쉐이커 녹음 1회만 재생합니다. 이전 합성 성공음·얼음음은 제거했습니다. 왼쪽 위 사운드 1/2 버튼으로 비교하며 선택은 브라우저에 유지됩니다. 원본 파일은 수정하지 않았습니다.
- 사운드 1: 제공된 shaker_01.wav의 0.48–0.98초. 사운드 2: shaker_02.wav의 2.47–2.97초. 각각 0.5초, 48kHz/16bit/stereo WAV로 저장하며 피크 0.7에 맞추고 앞 5ms·뒤 35ms 페이드를 적용했습니다. 파일은 audio/shaker_01_hit.wav, audio/shaker_02_hit.wav입니다. 원음의 피치·속도는 바꾸지 않았습니다. 제공 음원의 외부 배포 권리는 별도 확인이 필요합니다.
- 실패는 짧고 낮은 실패음과 붉은 표시만 추가합니다. 실패가 새 손동작이나 얼음 소리를 만들지는 않습니다. 직전 성공의 손동작이 아직 끝나지 않았다면 그 동작과 얼음 소리는 자연스럽게 마무리됩니다.
- 재입력으로 성공 동작이 교체되면 이전 얼음 소리도 교체합니다. 타격/얼음 두 채널까지만 사용합니다. 한 렌더 프레임 안에 입력이 여러 번 겹치면 최신 표시 동작만 소리로 내며, 이전 소리를 몰아서 재생하지 않습니다.
- ESC·탭 비활성화·화면 이탈은 재생 중인 효과음을 끊습니다. 재개할 때 같은 이벤트의 소리를 반복하지 않습니다. 옵션의 **기믹 효과음 · 병따기 / 쉐이킹**으로 함께 끌 수 있습니다. BGM은 별개입니다.
- 성공·실패 시각 효과는 최대 12개/0.55초로 제한하고 게임 시계와 함께 멈춥니다. OS의 동작 줄이기 설정에서는 반동·잔상·튀는 파편을 생략합니다.
- GPT 완료 대기는 기존 0.85초를 유지하되, 전체 화면 팝업으로 마지막 손동작을 가리지 않습니다. 완료 연출은 제조 시간에 더하지 않습니다.
- `shake-polish.js`: 피드백 렌더/녹음 효과음 선택/일시정지 정리. `tools/test_shake_polish_ui.cjs`: 기존/GPT의 입력당 소리 횟수, 실패 분리, 음소거·재시도·화면 이탈, 마지막 동작, 점수 유지, 동작 줄이기 검수.

### 병따기 연출과 기믹 화면

- 실제 `item_beer` 병 이미지를 확대하고, 뚜껑 중심을 판정 원의 중심에 맞춥니다. 현행 `prep_action=open` 재료는 맥주 하나입니다. 뚜껑 분리는 이 원본 그림의 영역을 사용하며 다른 병 이미지에 범용 적용하는 규칙은 아닙니다.
- Space 또는 화면 버튼으로 시작하고, 줄어드는 원이 목표 원에 겹칠 때 다시 누릅니다. 성공하면 뚜껑만 회전하며 날아가고 병 입구·작은 파편·팝 효과음을 표시합니다. 실패/시간 초과는 뚜껑이 찌그러지고 병따개가 미끄러지는 짧은 연출로 구분합니다.
- 판정 반경·접근 시간·실패 감점은 기존 데이터 그대로입니다. 연출 때문에 별도 실패나 재입력 대기시간을 만들지 않습니다. 완료 연출은 제조시간에 더하지 않으며, ESC·탭 비활성화 시 뚜껑 동작과 진행이 함께 멈춥니다.
- 원본 규칙은 성공 연출 0.65초 후 마치기/다음 버튼을 누릅니다. GPT 규칙은 기존 0.85초 완료 대기 중 뚜껑 연출을 끝낸 뒤 자동 진행합니다. 기존 완료 팝업이 뚜껑을 가리지 않게 했습니다.
- 효과음은 녹음 리소스가 아닌 Web Audio 합성(짧은 압력음 + 금속음)입니다. 첫 클릭/키 입력 이후 재생 가능하며, 이벤트당 한 번만 울립니다. 옵션에서 병따기 효과음을 따로 끌 수 있습니다. BGM은 기존 공통 재생을 유지합니다.
- 다섯 기믹 모두 상·하단 내비게이션 띠, 제목/단계 배지, 누적시간 안내, 레시피 버튼을 제거했습니다. 판정·용량 등 플레이에 필요한 화면은 유지하고, 마치기/다음 버튼은 배경 위 우측 하단에 둡니다. 따르기 누르기 버튼은 하단 중앙입니다. 기믹 선택 버튼은 단독 연습에만 표시하여 영업 중 제조 흐름을 바꾸지 않습니다.
- `open-view.js`: 원본 병·병따개 픽셀 렌더와 소리. `core.js OPEN`: 성공/실패 이벤트·일시정지와 동기화한 연출 시계. `gimmick-polish.css`: 모든 기믹의 떠 있는 버튼 배치.
- `tools/test_open_ui.cjs`: 기존/GPT 성공·실패 점수, 소리 중복/음소거, 일시정지, 재시도, 5종 화면, 반응형/목록 복귀 검수.

### 따르기·필업 효과음

- 따르기/필업 화면 왼쪽 위 목표량 아래에서 사운드 1·2를 선택합니다. 선택은 브라우저에 저장하며 쉐이킹·스터와 독립적입니다. 기존/GPT 및 영업/단독 연습에서 공통 사용합니다.
- 사운드 1: 제공된 `pour.wav`의 5.62–7.12초, 100ms 겹침 연결 후 1.40초 반복 파일. 사운드 2: `pour_02.wav`의 7.85–10.65초, 120ms 겹침 연결 후 2.68초 반복 파일. 무음/큰 음량 변화 구간을 피하고 DC 제거·유사 음량 정규화·부드러운 피크 억제를 적용했습니다. 48kHz/16bit/stereo, 피치·재생 속도 및 원본 파일은 변경하지 않았습니다. `audio/pour_01_loop.wav`, `audio/pour_02_loop.wav`를 사용합니다.
- 키 입력 자체가 아니라 실제 유량에 맞춰 재생합니다. 병이 흐르기 전까지 무음이고, 길게 따를 때는 같은 재생 소스를 반복합니다. 병을 세우는 동안 남은 유량에 맞춰 음량이 감소하고 유량 0에서 80ms 페이드아웃합니다. 잔에 담긴 액체의 움직임만으로는 소리를 내지 않습니다.
- 재생 중 버전을 바꾸면 짧게 교차 전환합니다. 옵션/일시정지·음소거·다른 창 이동·화면 이탈·재시작 시 기존 소리는 정리합니다. 음원 로드에 실패해도 용량·판정·진행에는 영향이 없습니다. 제공 음원의 외부 배포 권리는 별도 확인이 필요합니다.
- 검수: `tools/test_pour_audio_ui.cjs` — 두 파일/두 규칙/따르기·필업, 유량 연동·연속 반복·선택 유지·마우스/키보드·음소거·중단·실패 시 진행 확인.

### 따르기·필업 — 웹 2D 유체 프로토타입

기존의 CSS 물줄기와 즉시 용량 증가를 입자 물리로 교체했습니다. 단독 미니게임과 바 영업의 따르기·필업, 기존/GPT 버전이 같은 구현을 사용합니다. 엔진·원본 CSV·노션은 변경하지 않았습니다.

**화면:** 병에 푸어러를 연결하고 병·물줄기·잔을 중앙으로 확대 배치합니다. 왼쪽 상세 패널 없이 좌측 상단에는 목표량·현재량만 표시하고, 좌측 하단 설명 문구는 표시하지 않습니다. 물줄기는 잔 입구를 통과해도 굵기가 갑자기 커지지 않으며 액체가 느려져 모일 때만 부드럽게 퍼집니다. 목표량에 도달해도 자동으로 멈추지 않으며 손을 놓아 조절합니다.

**사용:** 첫 화면의 기믹 미니게임 → 따르기 또는 필업. Space / 화면 버튼을 누르면 기울고, 놓으면 다시 섭니다. 조금씩 나눠 따를 수 있습니다. 마치기 버튼은 병을 세운 뒤 공중의 액체가 정리될 때까지 기다리고 다음 화면으로 갑니다. 대기 중 추가 입력과 중복 확정은 차단합니다.

### 공통 BGM

- 제공받은 **LUNA Track 01~04** 네 곡을 모든 화면에서 공통으로 재생합니다. 시작 화면·바 대화·재료 준비·제조·결과·정산·게임오버·설정에서 같은 플레이어를 사용하므로 화면 변경이나 일차 재시작으로 곡이 초기화되지 않습니다.
- 네 곡을 섞어 한 번씩 재생한 다음 다시 섞습니다. 한 묶음 안에 중복은 없으며 다음 묶음의 첫 곡도 직전 곡과 겹치지 않습니다. 한 곡 반복이 아니라 네 곡의 셔플 반복입니다.
- 브라우저 정책에 따라 **처음 클릭하거나 키를 누른 뒤 시작**합니다. 게임 일시정지·메뉴·다른 탭에서도 BGM은 계속 재생되며, 음악만 끄려면 **ESC 옵션 → 공통 BGM**을 사용합니다. 껐다 켜면 중단한 위치부터 이어집니다.
- 기본 음량은 **30%**입니다. 설정의 음량 슬라이더와 켜짐/꺼짐은 해당 브라우저에 보관되며, 더미 효과음 설정과는 별개입니다. 새로고침 후 재생 위치까지 복원하는 기능은 아닙니다.
- 원본 24비트 WAV는 수정하지 않았습니다. `assets/audio/`의 AAC 192kbps 웹용 사본 네 개만 배포합니다. `tools/import_bgm.py <원본 음원 폴더>`로 macOS에서 다시 만들 수 있으며 변환 전후 원본 해시를 비교합니다.
- 음원 하나를 불러오지 못하면 다음 곡을 시도합니다. 전부 실패하면 음악만 정지하고 설정에 안내하며, 영업 진행을 막지 않습니다. 파일 문제를 해결한 뒤 BGM을 껐다 켜면 다시 시도합니다.

시작 화면에서 일차와 시작 구간을 고른 뒤 **영업 시작**을 누르세요. 먼저 0일차 전체 흐름을 보거나, 99일차의 **단골 손님 영업부터**를 골라 두 명 동시 입장·재제조를 확인하는 것을 권합니다. 99일차 제조 연습에서는 모든 칵테일을 바로 고를 수 있습니다.

| 쉐이킹·스터 | 쉐이킹은 실제 입력 횟수만 판정하고 지나간 박자를 자동 실패로 세지 않음. 스터는 엔진과 같은 순차 입력·한 바퀴 제한시간·입력 기반 숟가락/얼음 움직임 적용 |
| 단계 진행 | 병따기·쉐이킹·스터 완료 후 0.85초 피드백 뒤 자동 진행. 병따기 미완료 건너뛰기 차단, 믹스는 현재 결과로 종료 가능. 전환 시간은 제조시간에서 제외 |
| 제조 결과 | 감점 원인·다음 시도 힌트·단계별 결과·개인 최고점. 1.1초 확인 후 제공 / 같은 구성 재도전 / 다시 준비 |
| 음용·정산 | 일반 손님 수령 → 음용 → 빈 잔 → 반응. 정산 상단에 평가·최고 연속·목표 달성 결과와 재도전 버튼 |
| 알림·안전 | 작은 합성 판정·입장 알림음, 창 포커스 이탈 시 옵션을 열어 정지. 기존 공통 BGM은 유지 |

난이도별 **쉐이킹 입력 / 스터 회전**은 편안하게 12/6, 보통 16/8, 도전 20/10입니다. 제조·메뉴 중 손님 타이머는 기존처럼 멈춥니다. 제조를 빨리 끝내는 경쟁 대신 정확도와 바 화면에서의 응대 선택에 집중합니다.

챌린지 유지비는 **시작 소지금 + 해금 레시피 가격의 중앙값 × 8 × 난이도 계수**를 반올림해 계산합니다. 계수는 0.24 / 0.40 / 0.55이며 시작 화면에서 실제 금액을 먼저 보여줍니다. 챌린지 이외 모드는 기존 일차 유지비를 사용합니다. 목표 보상과 연속 보너스는 기존 판매 수입에 중복 합산하지 않고 별도 잔액 변동으로 표시합니다.

즐겨찾기·레시피별 최고점·최근 20회 챌린지 결과는 이 브라우저의 `luna.bar.gpt.v1`에만 보관합니다. 영업 중간 세이브나 서버 전송은 아닙니다. 읽음 기록도 기존 버전과 별도 키를 사용합니다. F2 정답 채우기·강제 제조·배속·유지비 조정·조기 정산을 사용한 영업은 TEST로 구분하며, 이후 보상과 정식 완료 기록에서 제외합니다. 테스트 전 정상 제조로 달성한 개인 최고점은 유지됩니다.

이하 공통 설명 중 20회 쉐이킹·10회 스터, 목표/메모가 없는 원래 운영 규칙은 **기존 버전 기준**입니다. 개선버전의 차이는 위 표를 우선합니다. 제공된 칵테일 대표 그림을 사용하는 시각적 한계는 유지하며, 모든 완성 잔을 실제 내용물로 새로 합성한 것은 아닙니다.

검수: `tools/test_remix.cjs`(레시피·챌린지·정산·분리), `tools/test_remix_ui.cjs`(실제 브라우저 조작). 기존 검수기도 별도로 실행해 두 버전의 회귀를 확인합니다. 브라우저 검수 주소는 위의 `LUNA_TEST_URL`을 사용합니다.

빌드 레시피의 정상 믹스 도구는 **없음**입니다. 쉐이커·믹싱 글라스를 잘못 담으면 기존 `tool_mismatch_penalty`(현재 10점)를 한 번 적용합니다. 추가 믹스에 별도 감점을 중복 생성하지 않으며, 보조 도구인 병따개는 이 비교 대상이 아닙니다. 쉐이킹/스터 레시피의 도구 누락·불일치 판정은 기존과 같습니다.

서비스 패널·레시피·매출·단골 정보·설정을 열면 일반 손님 시간이 멈춥니다. 제조 준비·기믹·결과에서도 바 시간은 멈추고, 제조 기믹 시간은 실제 조작 구간에서만 누적됩니다. 다른 브라우저 탭으로 이동하면 진행을 멈춥니다.

## 하루 정산·유지비·게임오버

**영업 종료 → 하루 정산 화면 → 정산 확인 → 유지비 지불 성공 또는 게임오버**로 이어집니다.

- 정산 화면: 판매·팁·환불, 영업 시작 소지금, 당일 수입, 정산 전 소지금, 유지비, 예상 잔액 또는 부족액.
- 기준은 당일 매출만이 아니라 **현재 보유 소지금 전체**입니다. 주문별 수입은 이미 소지금에 들어 있으므로 다시 더하지 않습니다.
- 소지금 ≥ 유지비: 유지비를 한 번 차감. 정확히 같은 금액이면 0G로 정상 종료합니다.
- 소지금 < 유지비: 정산 확인 후 게임오버. 일부 금액을 임의 차감하지 않습니다.
- 게임오버에서는 같은 일차 재시작·일차 선택·로그 내보내기가 가능합니다. 재시작은 해당 영업의 잔액·진행을 초기화하고 테스트 유지비는 유지합니다.
- 종료/정산 확인이 중복 호출되어도 유지비가 중복 차감되지 않습니다.

현재 가져온 `days.csv`의 0~3일차 `upkeep_gold`는 모두 **0G**입니다. 99일차는 일차 행이 없어 QA 기본 0G를 사용합니다. 확정 금액을 임의로 바꾸지 않았습니다.

게임오버를 테스트하려면 시작 화면의 **유지비 테스트값**에 금액을 입력하세요. 빈칸은 원본 일차 값, 0은 명시적인 면제 테스트입니다. 음수·소수는 허용하지 않습니다. 이 값은 웹 세션에만 적용되며 원본 CSV는 바뀌지 않습니다.

빠른 확인: 99일차 제조 연습 시작 → F2 → 유지비 `450` 입력·적용 → **지금 영업 끝내고 정산 보기** → 정산 확인. 기본 소지금 300G 기준 150G가 부족하여 게임오버됩니다. F2 조기 종료는 미제공 주문을 매출에 포함하지 않으며, 검수용 호출이라는 기록을 로그에 남깁니다.

## 더미·웹 재현 범위와 차이

이것은 **Unity 빌드가 아니라 문서와 데이터에 기반한 독립 웹 프로토타입**입니다. 웹 테스트가 통과했다고 엔진의 버그가 해결되었다는 뜻은 아닙니다.

1. 프로젝트 그래픽과 게임 한글 폰트를 복사해서 사용했습니다(에셋 연결 253개, 같은 파일을 공유하는 키 포함). 빠진 이미지는 `0. 더미(임시) 리소스`의 재료·레시피·인벤토리 그림으로 연결했습니다. 그 폴더에도 전용 그림이 없는 재료 19종은 제공된 공용 병 그림과 실제 재료 이름을 사용하고 호버에 `전용 이미지 미제공`을 표시합니다. CSS로 새 병 그림을 만들지 않습니다. 전용 완성 칵테일 그림도 없는 경우 해당 잔 이미지를 임시 사용합니다.
2. 일반 손님 CSV의 일부 의상 ID는 그래픽 폴더에 일대일 대응 파일이 없습니다. 누락 시 CSV의 성별 기본 조합 전체로 복귀하고 `appearance_fallback` 로그에 남깁니다. 없는 의상을 임의로 긴팔로 바꾼 채 팔 장식을 남기지 않습니다. 표정 리소스 미제공 시 기본 외형을 유지합니다.
3. 쉐이킹·스터는 연결된 현행 엔진 코드와 프리팹을 대조했습니다. 따르기·필업은 웹 전용 2D 유체와 잔 도착량 판정으로 확장했습니다. **Unity 입력 감각·물리 결과와 동일하지는 않습니다.** 각 차이는 상단의 기믹별 설명을 참조합니다.
4. `fx`·`sfx`는 대기 순서를 지키는 더미 섬광·선택적 합성 효과음입니다. 실제 사운드 파일·최종 연출·컷씬은 포함하지 않았습니다. 기본 효과음은 꺼져 있습니다.
5. 논리 화면은 **1280×720 / 16:9 고정**입니다. 큰 화면에서는 같은 비율로 확대하고, 작은 브라우저에서는 전체 화면을 균일 축소하며 남는 영역은 검정 여백으로 둡니다. 반응형 재배치로 구도나 기준선이 바뀌지 않습니다. 최종 Unity 카메라 좌표/픽셀 퍼펙트 렌더링까지 보증하는 것은 아닙니다.
6. 단골 정보는 아래 UI 문서 기준의 전체 화면 목록·상세 팝업입니다. 원본 수첩의 `desc/taste/history/secret`를 새 UI 항목에 임의 배치하지 않습니다. 아직 대응 원고가 없는 항목은 `원고 연결 대기`, 미해금 항목은 `???`입니다. 원본 `dossier.csv`와 임계값은 그대로 유지합니다.
7. QA 원문 선택지에는 `1부/2부`나 평판 테스트가 남아 있습니다. 원문은 보존하고 일반 UI 명칭만 **일반 손님 영업 / 단골 손님 영업**으로 통일했습니다. 평판은 QA effects 호환용 내부 값일 뿐 정상 영업 기능으로 추가하지 않았습니다.
8. 일반 손님 주문 목록을 몰래 보여주지 않습니다. 현재 좌석 대사·되묻기로 주문을 확인합니다. 원본 0일차 튜토리얼에는 과거의 좌측 주문표 설명이 남아 있어 현행 UI와 다릅니다.
9. 외부 거리·집·컷씬·게임 저장·네트워크 분석 전송은 범위 밖입니다. 바 중간 저장은 만들지 않았습니다. 읽은 대사 ID만 브라우저 localStorage에 기록하며, 영업 상태·돈·플래그를 게임 세이브로 저장하지 않습니다.

### 스터·쉐이킹 시안 적용

- 전달받은 바 내부 폴더의 스터 시안 `10.png`(3840×2160), 쉐이킹 시안 `11.jpg`(1920×1080)를 1280×720 화면 구성에 맞춰 참고했습니다. 시안 전체를 배경 한 장으로 띄우는 방식이 아니라 조작 키·경로·타이머·게이지가 실제 기믹 상태에 반응합니다.
- **스터**: 왼쪽 루나 동작 / 같은 얼음의 측면창, 오른쪽 믹싱 글라스 윗면 / W·D·S·A / 남은 제한시간 링 / 하단 결과 게이지. 다음 키는 청록색, 현재 방향은 밝은 키로 구분합니다. 키보드와 화면 키 클릭이 같은 입력을 호출합니다.

### 재료 담기 첫 화면

- 칵테일을 선택할 때마다 레시피 카드는 닫힌 상태로 시작합니다. 왼쪽 아래 레시피 버튼으로 필요할 때 열고, ×로 닫습니다. 이전 제조에서 열어 두었어도 다음 선택에 이어지지 않습니다.
- 하단 선택 재료 트레이의 배경만 불투명도 80%로 표시합니다. 담은 재료 이미지·이름·삭제 버튼은 투명해지지 않습니다.
- 가운데 선반 인디케이터에는 점만 표시합니다. 선반 이름과 A/D 안내 줄을 제거하고 A는 왼쪽 화살표 아래, D는 오른쪽 화살표 아래에 작게 표시합니다. 기존 A/D 슬라이드 이동과 점 클릭은 그대로 동작합니다.

### 스터 녹음 효과음과 입력 피드백

- 기존/GPT, 영업/단독 연습 공통. 화면 왼쪽 위 사운드 1/2 선택은 브라우저에 저장하며 쉐이킹 선택과 별개입니다.
- 제공된 Stir_01.wav의 0.65–3.10초, Stir_02.wav의 0.50–3.80초에서 무음을 제외했습니다. 양끝 80ms 교차 연결 후 실제 길이는 2.37초/3.22초, 48kHz·16bit·스테레오입니다. 피크 0.7 이하로 조정하고 피치·재생속도는 유지했습니다. 원본 파일은 수정하지 않았으며 외부 배포 권리는 별도 확인이 필요합니다.
- W로 시작할 때는 무음. 올바른 방향 입력이 기존 손동작을 시작하면 녹음 재생을 시작하고, 연속 입력 중에는 같은 재생 위치를 유지합니다. 손동작 예산(stirMotionPending)이 끝나면 80ms 페이드아웃합니다. 잘못된 입력·시간 초과는 새 소리나 손동작을 만들지 않습니다. 이전 정상 동작이 남았다면 그 구간만 마무리합니다.
- ESC·음소거·화면 이탈·재시작·음원 변경 시 현재 소리를 정리합니다. 재개/음소거 해제만으로 재생하지 않고 다음 정상 입력부터 재생합니다. 음원 로드 실패는 게임 진행을 막지 않고 화면에 안내하며 합성 성공음으로 대체하지 않습니다.
- 손동작과 함께 이어지는 물결 잔상, 정상 입력 키의 짧은 발광, 한 바퀴 결과 테두리 반응을 추가했습니다. 판정·시간·점수·12FPS 손 애니메이션은 그대로이며, 동작 줄이기에서는 회전 잔상과 확산을 생략합니다. GPT의 기존 완료 팝업/합성 판정음은 스터 화면에서 제외해 마지막 동작과 녹음 소리를 가리지 않습니다.
