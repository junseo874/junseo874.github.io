# L.U.N.A 바 영업 플레이테스트

## 실행

폴더의 **index.html을 Chrome 또는 Edge로 열면 됩니다.** 서버 설치나 npm 설치 없이 실행하도록 만들었습니다. 한글 폰트와 이미지가 모두 폴더에 포함되어 있으므로, 전달할 때는 index.html만 보내지 말고 폴더 전체를 보내세요.

편집 원본: GitHub Pages 저장소의 `bar-playtest/` 폴더. 사이트 로비에서 **바 영업 플레이테스트**로 들어옵니다. **ESC 옵션 → 로비로 돌아가기**로 되돌아갈 수 있습니다.

사이트 로컬 주소: http://127.0.0.1:8123/bar-playtest/ (`python3 serve.py`는 저장소 루트에서 실행). 기존 http://127.0.0.1:8765 주소도 이 폴더를 가리키며 별도의 수정본이 아닙니다.

브라우저 검수 시 `LUNA_TEST_URL=http://127.0.0.1:8123/bar-playtest/`를 지정하면 하위 페이지 경로로 검수합니다. 원본 CSV를 자동 동기화하지 않으며 데이터 재반영은 아래 가져오기 도구를 명시적으로 실행해야 합니다.

### 공통 BGM

- 제공받은 **LUNA Track 01~04** 네 곡을 모든 화면에서 공통으로 재생합니다. 시작 화면·바 대화·재료 준비·제조·결과·정산·게임오버·설정에서 같은 플레이어를 사용하므로 화면 변경이나 일차 재시작으로 곡이 초기화되지 않습니다.
- 네 곡을 섞어 한 번씩 재생한 다음 다시 섞습니다. 한 묶음 안에 중복은 없으며 다음 묶음의 첫 곡도 직전 곡과 겹치지 않습니다. 한 곡 반복이 아니라 네 곡의 셔플 반복입니다.
- 브라우저 정책에 따라 **처음 클릭하거나 키를 누른 뒤 시작**합니다. 게임 일시정지·메뉴·다른 탭에서도 BGM은 계속 재생되며, 음악만 끄려면 **ESC 옵션 → 공통 BGM**을 사용합니다. 껐다 켜면 중단한 위치부터 이어집니다.
- 기본 음량은 **30%**입니다. 설정의 음량 슬라이더와 켜짐/꺼짐은 해당 브라우저에 보관되며, 더미 효과음 설정과는 별개입니다. 새로고침 후 재생 위치까지 복원하는 기능은 아닙니다.
- 원본 24비트 WAV는 수정하지 않았습니다. `assets/audio/`의 AAC 192kbps 웹용 사본 네 개만 배포합니다. `tools/import_bgm.py <원본 음원 폴더>`로 macOS에서 다시 만들 수 있으며 변환 전후 원본 해시를 비교합니다.
- 음원 하나를 불러오지 못하면 다음 곡을 시도합니다. 전부 실패하면 음악만 정지하고 설정에 안내하며, 영업 진행을 막지 않습니다. 파일 문제를 해결한 뒤 BGM을 껐다 켜면 다시 시도합니다.

시작 화면에서 일차와 시작 구간을 고른 뒤 **영업 시작**을 누르세요. 먼저 0일차 전체 흐름을 보거나, 99일차의 **단골 손님 영업부터**를 골라 두 명 동시 입장·재제조를 확인하는 것을 권합니다. 99일차 제조 연습에서는 모든 칵테일을 바로 고를 수 있습니다.

## 두 가지 플레이 버전

시작 화면 왼쪽 위에서 **기존 버전 / GPT 개선버전**을 선택합니다. 일반 주소는 기존 버전으로 열리며, `?version=gpt`를 붙이면 개선버전 설정 화면으로 바로 들어갑니다. 진행 중에는 **ESC → 일차 / 시작 구간 변경 → 일차 선택으로**에서 탭을 바꿉니다. 바꾸면 현재 영업은 초기화됩니다.

### GPT 개선버전 — 비교 플레이용 실험

추천 시작은 **전체 해금 · 8팀 챌린지 · 보통**입니다. 기존 대본 전체 흐름, 일반 손님 영업, 단골 대화, 제조 연습도 선택할 수 있습니다. 이 모드는 재미를 비교하기 위한 실험이며 **기존 버전·원본 CSV·단골 대사·Unity·Notion 기획을 변경하지 않습니다.**

| 개선 요소 | 적용 내용 |
| --- | --- |
| 한 판의 목표 | 일반 손님 8팀을 맞고 유지비를 지불하는 챌린지. 첫 주문은 단순한 레시피, 이후 점진적으로 후보 확대. 이 모드만 단골 대본 없이 정산 |
| 난이도 3종 | 편안하게 / 보통 / 도전. 손님 간격·인내심·믹스 횟수·챌린지 유지비 조정 |
| 영업 목표 | Good 이상 4잔 +30G, 메뉴 3종 +20G, Good 이상 3연속 +20G. 정산 직전 한 번 지급 |
| 연속 보너스 | 주문에 맞는 Good 이상 두 번째 잔부터 +3G, 이후 +3G씩 증가해 잔당 최대 +12G. 낮은 등급·오주문·손님 이탈 시 연속 종료 |
| 주문 안내 | 현재 손님의 다음 행동 안내, 들은 주문 메모, 준비 재료 체크. 주문 메모·체크는 시작 화면 또는 영업 목표 창에서 끌 수 있음 |
| 좌석 상태 | 빈자리·손님 있음·인내심 경고·퇴장을 점 인디케이터로 표시. 경고는 색뿐 아니라 느낌표도 표시 |
| 레시피 탐색 | 빌드 / 스터 / 쉐이킹 / 즐겨찾기 필터, 이름 검색, 상세를 먼저 확인한 뒤 제조 선택 |
| 따르기 | 병 각도에 따른 유량·손을 놓았을 때 예상 종료량 표시. Space 누르기/놓기는 웹 실험 조작이며 문서의 A/D 구현으로 바꾼 것은 아님 |
| 쉐이킹·스터 | 쉐이킹은 실제 입력 횟수만 판정하고 지나간 박자를 자동 실패로 세지 않음. 스터는 순차 입력·한 바퀴 제한시간을 표시하고 동시 연타 방지 |
| 단계 진행 | 병따기·쉐이킹·스터 완료 후 0.85초 피드백 뒤 자동 진행. 미완료 상태 건너뛰기 차단. 전환 시간은 제조시간에서 제외 |
| 제조 결과 | 감점 원인·다음 시도 힌트·단계별 결과·개인 최고점. 1.1초 확인 후 제공 / 같은 구성 재도전 / 다시 준비 |
| 음용·정산 | 일반 손님 수령 → 음용 → 빈 잔 → 반응. 정산 상단에 평가·최고 연속·목표 달성 결과와 재도전 버튼 |
| 알림·안전 | 작은 합성 판정·입장 알림음, 창 포커스 이탈 시 옵션을 열어 정지. 기존 공통 BGM은 유지 |

난이도별 **쉐이킹 입력 / 스터 회전**은 편안하게 12/6, 보통 16/8, 도전 20/10입니다. 제조·메뉴 중 손님 타이머는 기존처럼 멈춥니다. 제조를 빨리 끝내는 경쟁 대신 정확도와 바 화면에서의 응대 선택에 집중합니다.

챌린지 유지비는 **시작 소지금 + 해금 레시피 가격의 중앙값 × 8 × 난이도 계수**를 반올림해 계산합니다. 계수는 0.24 / 0.40 / 0.55이며 시작 화면에서 실제 금액을 먼저 보여줍니다. 챌린지 이외 모드는 기존 일차 유지비를 사용합니다. 목표 보상과 연속 보너스는 기존 판매 수입에 중복 합산하지 않고 별도 잔액 변동으로 표시합니다.

즐겨찾기·레시피별 최고점·최근 20회 챌린지 결과는 이 브라우저의 `luna.bar.gpt.v1`에만 보관합니다. 영업 중간 세이브나 서버 전송은 아닙니다. 읽음 기록도 기존 버전과 별도 키를 사용합니다. F2 정답 채우기·강제 제조·배속·유지비 조정·조기 정산을 사용한 영업은 TEST로 구분하며, 이후 보상과 정식 완료 기록에서 제외합니다. 테스트 전 정상 제조로 달성한 개인 최고점은 유지됩니다.

이하 공통 설명 중 20회 쉐이킹·10회 스터, 목표/메모가 없는 원래 운영 규칙은 **기존 버전 기준**입니다. 개선버전의 차이는 위 표를 우선합니다. 제공된 칵테일 대표 그림을 사용하는 시각적 한계는 유지하며, 모든 완성 잔을 실제 내용물로 새로 합성한 것은 아닙니다.

검수: `tools/test_remix.cjs`(레시피·챌린지·정산·분리), `tools/test_remix_ui.cjs`(실제 브라우저 조작). 기존 검수기도 별도로 실행해 두 버전의 회귀를 확인합니다. 브라우저 검수 주소는 위의 `LUNA_TEST_URL`을 사용합니다.

| 상태 확인 | F2 |

단골 손님 코스터는 `order` 대사 완료 시 자동 생성됩니다. 일반 손님에게는 직접 줘야 합니다. 단골 좌석은 L/R 두 자리이고 일반 손님은 L/M/R 세 자리입니다.

병따기·쉐이킹·따르기·필업에서 A/D 등 다른 기믹의 키는 시작·시간 누적·판정에 사용하지 않습니다. 스터만 WASD/방향키를 사용합니다. 선택지는 카메라 전환 완료 후 첫 활성 항목에 포커스하며, 키를 길게 눌러도 다음 분기를 연속 확정하지 않습니다.

빌드 레시피의 정상 믹스 도구는 **없음**입니다. 쉐이커·믹싱 글라스를 잘못 담으면 기존 `tool_mismatch_penalty`(현재 10점)를 한 번 적용합니다. 추가 믹스에 별도 감점을 중복 생성하지 않으며, 보조 도구인 병따개는 이 비교 대상이 아닙니다. 쉐이킹/스터 레시피의 도구 누락·불일치 판정은 기존과 같습니다.

서비스 패널·레시피·매출·단골 정보·설정을 열면 일반 손님 시간이 멈춥니다. 제조 준비·기믹·결과에서도 바 시간은 멈추고, 제조 기믹 시간은 실제 조작 구간에서만 누적됩니다. 다른 브라우저 탭으로 이동하면 진행을 멈춥니다.

## 하루 정산·유지비·게임오버

**영업 종료 → 하루 정산 화면 → 정산 확인 → 유지비 지불 성공 또는 게임오버**로 이어집니다.

- 정산 화면: 판매·팁·환불, 영업 시작 소지금, 당일 수입, 정산 전 소지금, 유지비, 예상 잔액 또는 부족액.
- 기준은 당일 매출만이 아니라 **현재 보유 소지금 전체**입니다. 주문별 수입은 이미 소지금에 들어 있으므로 다시 더하지 않습니다.
- 소지금 ≥ 유지비: 유지비를 한 번 차감. 정확히 같은 금액이면 0G로 정상 종료합니다.
- 소지금 < 유지비: 정산 확인 후 게임오버. 일부 금액을 임의 차감하지 않습니다.
- 게임오버에서는 같은 일차 재시작·일차 선택·로그 내보내기가 가능합니다. 재시작은 해당 영업의 잔액·진행을 초기화하고 테스트 유지비는 유지합니다.
- 종료/정산 확인이 중복 호출되어도 유지비가 중복 차감되지 않습니다.

현재 가져온 `days.csv`의 0~3일차 `upkeep_gold`는 모두 **0G**입니다. 99일차는 일차 행이 없어 QA 기본 0G를 사용합니다. 확정 금액을 임의로 바꾸지 않았습니다.

게임오버를 테스트하려면 시작 화면의 **유지비 테스트값**에 금액을 입력하세요. 빈칸은 원본 일차 값, 0은 명시적인 면제 테스트입니다. 음수·소수는 허용하지 않습니다. 이 값은 웹 세션에만 적용되며 원본 CSV는 바뀌지 않습니다.

빠른 확인: 99일차 제조 연습 시작 → F2 → 유지비 `450` 입력·적용 → **지금 영업 끝내고 정산 보기** → 정산 확인. 기본 소지금 300G 기준 150G가 부족하여 게임오버됩니다. F2 조기 종료는 미제공 주문을 매출에 포함하지 않으며, 검수용 호출이라는 기록을 로그에 남깁니다.

## 더미·웹 재현 범위와 차이

이것은 **Unity 빌드가 아니라 문서와 데이터에 기반한 독립 웹 프로토타입**입니다. 웹 테스트가 통과했다고 엔진의 버그가 해결되었다는 뜻은 아닙니다.

1. 프로젝트 그래픽과 게임 한글 폰트를 복사해서 사용했습니다(에셋 연결 253개, 같은 파일을 공유하는 키 포함). 빠진 이미지는 `0. 더미(임시) 리소스`의 재료·레시피·인벤토리 그림으로 연결했습니다. 그 폴더에도 전용 그림이 없는 재료 19종은 제공된 공용 병 그림과 실제 재료 이름을 사용하고 호버에 `전용 이미지 미제공`을 표시합니다. CSS로 새 병 그림을 만들지 않습니다. 전용 완성 칵테일 그림도 없는 경우 해당 잔 이미지를 임시 사용합니다.
2. 일반 손님 CSV의 일부 의상 ID는 그래픽 폴더에 일대일 대응 파일이 없습니다. 누락 시 CSV의 성별 기본 조합 전체로 복귀하고 `appearance_fallback` 로그에 남깁니다. 없는 의상을 임의로 긴팔로 바꾼 채 팔 장식을 남기지 않습니다. 표정 리소스 미제공 시 기본 외형을 유지합니다.
3. 쉐이킹은 엔진의 이동 노드 조작을 브라우저용 타이밍 구간으로 간소화했습니다. 60 BPM·20회 성공 비율 판정은 가져왔지만 **Unity 입력 감각과 난도가 동일하지는 않습니다**. 병따기·따르기·스터도 웹 좌표계로 재현했습니다.
4. `fx`·`sfx`는 대기 순서를 지키는 더미 섬광·선택적 합성 효과음입니다. 실제 사운드 파일·최종 연출·컷씬은 포함하지 않았습니다. 기본 효과음은 꺼져 있습니다.
5. 논리 화면은 **1280×720 / 16:9 고정**입니다. 큰 화면에서는 같은 비율로 확대하고, 작은 브라우저에서는 전체 화면을 균일 축소하며 남는 영역은 검정 여백으로 둡니다. 반응형 재배치로 구도나 기준선이 바뀌지 않습니다. 최종 Unity 카메라 좌표/픽셀 퍼펙트 렌더링까지 보증하는 것은 아닙니다.
6. 단골 정보는 아래 UI 문서 기준의 전체 화면 목록·상세 팝업입니다. 원본 수첩의 `desc/taste/history/secret`를 새 UI 항목에 임의 배치하지 않습니다. 아직 대응 원고가 없는 항목은 `원고 연결 대기`, 미해금 항목은 `???`입니다. 원본 `dossier.csv`와 임계값은 그대로 유지합니다.
7. QA 원문 선택지에는 `1부/2부`나 평판 테스트가 남아 있습니다. 원문은 보존하고 일반 UI 명칭만 **일반 손님 영업 / 단골 손님 영업**으로 통일했습니다. 평판은 QA effects 호환용 내부 값일 뿐 정상 영업 기능으로 추가하지 않았습니다.
8. 일반 손님 주문 목록을 몰래 보여주지 않습니다. 현재 좌석 대사·되묻기로 주문을 확인합니다. 원본 0일차 튜토리얼에는 과거의 좌측 주문표 설명이 남아 있어 현행 UI와 다릅니다.
9. 외부 거리·집·컷씬·게임 저장·네트워크 분석 전송은 범위 밖입니다. 바 중간 저장은 만들지 않았습니다. 읽은 대사 ID만 브라우저 localStorage에 기록하며, 영업 상태·돈·플래그를 게임 세이브로 저장하지 않습니다.

## 검수

### 레시피·재료 담기와 캐릭터 애니메이션

- 사용자 제공 시안의 **좌측 레시피 / 중앙 선반 / 하단 선택 재료 / 우측 제조 시작** 구성을 적용했습니다. 레시피는 접고 펼칠 수 있고 본문만 독립 스크롤합니다. 선택 재료의 ×를 누르면 선택이 해제되며, 뒤로 가기는 기존대로 모든 선택을 초기화한 후 레시피 목록으로 돌아갑니다.
- 잔 → 도구 → 술 선반 → 냉장고를 **A/D·방향키·좌우 화살표·네 개의 점**으로 이동합니다. 네 화면을 유지하고 0.45초 수평 슬라이드로 이동합니다. 슬롯이 부족하면 같은 선반 안에서 별도 페이지 이동을 제공합니다. 99일차의 해금 항목을 누락하지 않습니다.
- **병따개**를 도구 선반·선택 목록에 추가했습니다. 쉐이커/믹싱 글라스와 동시에 담을 수 있는 보조 도구로서, 믹스 도구를 대체하거나 빌드에 도구 감점을 추가하지 않습니다. 병따기 실행 여부는 기존 CSV의 병 재료 `prep_action=open`이 결정합니다. 병따개 선택을 신규 필수 제조 조건으로 만들거나 원본 CSV에 항목을 추가하지 않았습니다.
- **말풍선은 재료 호버/키보드 포커스 안내입니다.** `shelf_items.name.ko/en`, `desc.ko/en`에서 이름과 짧은 소개를 그대로 읽습니다. 포인터가 떠나거나 선반을 바꾸면 닫히고, 클릭하면 재료를 담습니다. 소개를 별도로 창작하지 않았습니다.
- 규격 문서의 잔 45×95, 도구 70×115, 술병 57×171, 냉장고 상단 93×119·하단 93×223을 기준으로 상대 크기를 맞췄습니다. 재료 선반은 16:9 배경 전체를 1280×720 화면에 맞추고, 원화 기준 재료 위치도 같은 배율로 표시합니다. 원본 파일은 리사이즈/덮어쓰기하지 않았습니다.
- 일반 손님 남녀 각각 몸·윗얼굴·아랫얼굴의 **실제 4프레임 대화 시트**를 연결했습니다. 한 손님에 속한 파츠는 같은 시계로 재생합니다. 머리·의상·장식과 CSV 금지 조합은 그대로 유지합니다. 같은 성격의 손님이 여러 명이어도 현재 앞자리 대화에 해당하는 손님만 말합니다.
- **눈 깜빡임·몸의 기본 Idle은 대사 유무와 무관하게 반복하고, 말하는 입만 타이핑 중에 재생합니다.** 타이핑 완료·전체 출력 시 입은 기본 하관으로 돌아가지만 눈·몸의 재생 시계는 멈추거나 처음부터 리셋되지 않습니다. 두 손님 중 다른 사람이 말하거나 루나가 말할 때도 동일합니다. 기본 하관에 포함된 고개 움직임은 몸과 같은 프레임으로 계속 맞춥니다.
- 좌석 이동으로 말풍선이 숨겨질 때는 기존 요청대로 현재 입 동작의 한 사이클만 자연스럽게 마무리합니다(최대 1초, 새 반복 없음). 그동안과 이후에도 눈·Idle은 계속 재생합니다. 이동한 자리의 새 대사는 카메라 도착 후 시작합니다.
- 일반 손님 리소스의 `talk` 폴더에 있는 **공용 눈 깜빡임 시트**는 Idle에서도 사용합니다. 대화용 몸 시트는 얼굴이 빠진 동일 이미지 4장이므로, 얼굴이 온전한 기본 몸 이미지를 유지하고 눈·입만 겹쳐 표시합니다. **eyes 4, mouth 4·5의 대응 애니메이션은 미제공**이므로 해당 파츠만 원래 정적 그림으로 유지합니다. 예를 들어 mouth 5여도 eyes 1의 눈 깜빡임은 계속되고, eyes 4여도 mouth 1은 말할 때 움직입니다. 다른 얼굴로 대체하거나 손님 전체를 멈추지 않습니다. 한 장짜리 단골 성공·실패 등 특수 표정은 원본에 애니메이션이 없어 정적 표시를 유지합니다.
- 크리스·포트·아일리·삼호·부비의 기본/대화 시트를 재생하며 포트의 기쁨·분노·진지함, 엔진 주소에 연결된 성공·실패·놀람·취함 표정도 사용합니다. 미제공 표정은 기본 외형입니다. 기존 루나 1인칭 대화 구성은 변경하지 않았습니다.
- 캐릭터 애니메이션 속도는 엔진의 `CharacterPart.SetClipSpeed()`와 `CH.controller`를 기준으로 **1사이클 = 1초**로 맞췄습니다. 원본 클립 샘플레이트 12 FPS와 실제 재생 속도는 다릅니다. 엔진은 `Clip.length / TARGET_LENGTH(1초)`를 적용하므로 일반 4프레임은 초당 4프레임, 부비 8프레임은 초당 8프레임으로 한 바퀴를 돕니다. 기존 웹의 12 FPS 직재생보다 일반 4프레임은 약 0.33배 속도입니다. 입장/퇴장은 웹용 위치·알파 전환이며 별도 걷기 시트를 새로 만들지는 않았습니다.
- 삼호의 음용 후 포즈는 몸에 상체·머리가 이미 포함되어 있어 음용 몸+아랫얼굴만 조합합니다. 유휴 머리를 더 얹지 않습니다. 서빙 직후 짧게 재생하고 대본 표정으로 돌아옵니다.
- 551×530 공통 캔버스를 유지합니다. 단골 사람 캐릭터는 몸통의 잘린 선(y=440)을 상판 시작(y=500)에 맞추고, 팔·손은 그 아래로 내려오는 원본 그림 그대로 상판 위에 놓습니다. 포트의 진지함/놀람과 삼호의 성공/실패/취함 등 캔버스가 다른 포즈는 원본 몸통 기준선과 잘린 이미지의 위치를 보정합니다. 매 프레임 투명 여백을 잘라 위치가 흔들리는 방식은 쓰지 않습니다.
- 출력은 1280×720 고정이고, 바 단일 시점은 원화 960×540 영역, 2인 구도는 1280×720 영역을 사용합니다. 전체 배경 2041×792는 늘려 찌그러뜨리지 않습니다. 후경/중경/상판을 분리해 좌석 이동 시 각각 0.88/0.95/1의 이동량을 적용하며 0.55초간 부드럽게 전환합니다.
- 일반 손님은 투명 여백을 제외한 몸체 끝단을 원화 상판 시작 y=500에 맞춥니다. 단골은 손끝이 아닌 위의 몸통 기준선을 사용합니다. 부비는 기존처럼 발밑 y=535에 전신을 표시합니다. 선반은 각 이미지의 고정 알파 경계로 여백을 보정하므로 쉐이커·잔·병의 실제 밑면이 선반에 맞습니다.

### 스터·쉐이킹 시안 적용

- 전달받은 바 내부 폴더의 스터 시안 `10.png`(3840×2160), 쉐이킹 시안 `11.jpg`(1920×1080)를 1280×720 화면 구성에 맞춰 참고했습니다. 시안 전체를 배경 한 장으로 띄우는 방식이 아니라 조작 키·경로·타이머·게이지가 실제 기믹 상태에 반응합니다.
- **스터**: 왼쪽 루나 동작 / 손·컵 확대창, 오른쪽 믹싱 글라스 윗면 / W·D·S·A / 한 바퀴 진행 링 / 하단 결과 게이지. 다음 키는 청록색, 현재 방향은 밝은 키로 구분합니다. 키보드와 화면 키 클릭이 같은 입력을 호출합니다.
- **쉐이킹**: 왼쪽 루나 동작 / 손·쉐이커 확대창, 오른쪽 지그재그 경로 / 이동 표시 / 노란 타이밍 원 / 세로 결과 게이지. 노란 선 구간은 기존 웹의 실제 성공 시간대(한 박자의 59~91%)와 대응합니다. 경로는 끝에서 역방향으로 이어지므로 매 박자 시작점으로 순간 이동하지 않습니다.
- 프로젝트의 실제 스터 6프레임(970×550), 쉐이킹 8프레임(1280×720) 시트를 사용합니다. 원본 이미지 비율을 유지하고 본 화면과 확대창은 같은 프레임을 표시합니다. 루프는 웹 연출 기준 1초이며, 입력 대기·완료·일시정지 중에는 동작도 멈춥니다.
- 믹싱 글라스 **윗면 전용 파일은 제공 폴더에서 찾지 못했습니다.** 현재는 스터 시안의 컵 부분만 CSS로 잘라 표시하는 임시 연결입니다. 원본을 편집하거나 새 컵 그림을 만들지 않았습니다. 전용 리소스가 생기면 이 부분만 교체하면 됩니다.
- 스터 10회·한 바퀴 제한 2초, 쉐이킹 60 BPM·20회와 기존 점수 계산은 유지합니다. 성공/실패 이력은 화면 게이지 표시용으로만 추가했으며 저장 데이터나 CSV 구조를 추가하지 않았습니다. 오른쪽 시계는 현재 기믹 시간, 하단은 전체 제조의 순수 조작 시간입니다.
- **Unity 쉐이킹과 조작·난도가 완전히 같다는 의미는 아닙니다.** 이전 웹 타이밍 판정 위에 새 경로 화면을 연결한 것입니다. 엔진의 이동 노드 판정을 새로 구현하거나 변경하지 않았습니다.
- 확인 경로: 99일차 → 칵테일 제조 연습 → 드라이마티니(스터) 또는 진피즈(쉐이킹) → 재료 담기·따르기 이후 해당 기믹으로 진행합니다.
- `tools/test_mix_ui.cjs`: 키보드/마우스 스터 한 바퀴, 오입력·시간 초과, 쉐이킹 타이밍, 순서별 성공/실패 칸, 원본 애니메이션 프레임·확대창 동기화, 일시정지·레시피 열기 시 시간 정지, 다음 기믹 인계와 화면 배율을 검사합니다.

## 파일

- `index.html`, `styles.css`, `app.js`: 화면과 입력.
- `dossier.css`: 단골 목록·상세 팝업의 전용 화면 스타일.
- `bar-views.js`, `bar-views.css`: 시안 기반 재료 담기·레시피 패널과 캐릭터 프레임 렌더링. 게임 규칙/원본 CSV 스키마를 바꾸지 않는 화면 계층입니다.
- `core.js`: 대본 실행, 일반 손님 상태, 제조·서빙·정산.
- `data.js`: 실제 CSV를 읽기 전용으로 가져온 웹 스냅샷. 배열 ID와 텍스트는 원본 기준.
- `source-inventory.json`: CSV 원본 경로·해시와 그래픽 파일 출처.
- `assets/`: 복사한 그래픽과 한글 폰트.
- `tools/import_sources.py`: 같은 프로젝트의 CSV/그래픽으로 스냅샷을 다시 만들 때 사용. 원본 파일을 수정하지 않음.
- `tools/import_animation_art.py`: CSV 스냅샷을 유지한 채 실제 애니메이션·표정 이미지 연결만 갱신합니다. 전체 `import_sources.py` 재실행 후에는 이 파일도 실행해야 합니다.
- `tools/test_core.cjs`, `tools/test_browser.cjs`, `tools/test_dossier.cjs`, `tools/test_art_ui.cjs`, `tools/test_layout.cjs`, `tools/test_mix_ui.cjs`, `tools/test_speech_ui.cjs`: 재검수 스크립트. 브라우저 검수 스크립트는 현재 Mac의 런타임 경로를 사용함.

### 서비스 패널과 화면 배치

- 상단 내비게이션 바와 그 배경, DAY·영업 단계·전체 보기·일시정지·F2 버튼은 표시하지 않습니다. 좌측 상단에는 불투명도 96%의 작은 ? 도움말, 우측에는 재화만 표시합니다. 대사 기록은 Y, 옵션은 ESC, 검수 도구는 F2로 엽니다.
- 일반 손님의 좌측 하단 세 점은 L/M/R 시점에 대응합니다. 클릭 또는 A/D 이동 시 현재 점이 밝아집니다. 화면 양쪽 중앙 끝에는 작은 A/D만 표시하며 클릭으로도 옆 좌석으로 이동합니다. 단골의 자동 2인 구도는 변경하지 않았습니다.
- 서비스 패널 버튼은 좌측 하단 좌석 인디케이터 위에 있고, 패널은 버튼 위쪽으로 열립니다. Tab으로 열고 닫습니다. 기존 메뉴와 동일하게 대사와 영업 시간을 멈추고, 레시피·매출·단골 정보로 인계합니다. 패널 내 ↑/↓로 항목 이동, Enter로 선택 가능합니다. 다른 메뉴의 Tab 탐색과 제조 기믹 입력은 그대로 유지합니다.
- 재료 담기 배경은 상단/하단 UI 및 레시피 열림 여부와 무관하게 항상 1280×720입니다. 선반·재료의 크기와 위치는 변하지 않고, 레시피 카드는 왼쪽 위에 겹쳐 표시됩니다. 가려진 재료는 카드의 ×로 접은 뒤 선택합니다. 선택 재료 트레이·제조 시작·선반 인디케이터도 배경 위에 배치했습니다.
- 코스터 묶음은 우측 하단에 있습니다. 주문 되묻기는 코스터 바로 위에, 완성 칵테일 드래그 영역은 화면 중앙 하단에 배치합니다. 말풍선과도 겹치지 않게 분리했습니다.
- 뒤로 가기는 기존대로 선택한 잔·도구·재료를 모두 비우고 바 배경 위 레시피 목록으로 돌아갑니다.
- `tools/test_service_ui.cjs`: 하단 툴바 제거, 좌석 인디케이터, 서비스 패널 입력·시간 정지·메뉴 인계, 전체화면 선반, 레시피 오버레이 크기 불변, 상단 바 제거·Y/ESC/F2 단축키·한/영 화면 배치를 검수합니다.

### 대화 화면 시안 맞춤

- 빈 좌석의 “손님을 기다리는 중” 안내는 표시하지 않습니다. 제조가 가능한 주문의 레시피 바로가기 안내는 유지합니다.
- 실제 소지금 `progress.money`를 우측 상단 코인+숫자 HUD로 표시합니다. 시안의 9,999를 고정 출력하지 않으며, 매출·팁·환불·정산 결과가 같은 값에 반영됩니다. 코인은 웹 UI용 픽셀 SVG이고 원본 게임 리소스를 수정하지 않습니다.
- 1742×981 시안의 화면 대비 비율을 1280×720에 맞춰 말풍선 폭 538px, 기본 높이 124px, 대사 18px / 이름 20px로 조정했습니다. 기존 로컬 한글 폰트를 유지합니다. 긴 대사는 전체 원문을 기준으로 높이를 미리 확보하고, 타이핑 도중 말풍선 크기가 변하지 않습니다.
- 웹의 기본 타이핑은 이전보다 1.5배 빠릅니다(설정의 ×1 기준). 일반 손님 대사 출력 후 대기, 인내심, 캐릭터 애니메이션 속도는 변경하지 않았습니다. 원본 CSV 타이밍도 그대로 유지합니다.
- 말풍선 안의 조작 설명은 작은 다음 화살표로 정리했습니다. 자동 대사는 다음 입력 표시가 없으며, 조작 방식은 상단 ?에서 확인합니다.
- 좌측 하단 점은 14px, 시안처럼 회색과 청록빛 현재 시점 표시를 사용합니다.

### 재료 담기 첫 화면

- 칵테일을 선택할 때마다 레시피 카드는 닫힌 상태로 시작합니다. 왼쪽 아래 레시피 버튼으로 필요할 때 열고, ×로 닫습니다. 이전 제조에서 열어 두었어도 다음 선택에 이어지지 않습니다.
- 하단 선택 재료 트레이의 배경만 불투명도 80%로 표시합니다. 담은 재료 이미지·이름·삭제 버튼은 투명해지지 않습니다.
- 가운데 선반 인디케이터에는 점만 표시합니다. 선반 이름과 A/D 안내 줄을 제거하고 A는 왼쪽 화살표 아래, D는 오른쪽 화살표 아래에 작게 표시합니다. 기존 A/D 슬라이드 이동과 점 클릭은 그대로 동작합니다.
